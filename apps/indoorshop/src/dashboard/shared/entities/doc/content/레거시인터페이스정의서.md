## 1. 개요

본 문서는 내업 공정실적 자동수집 시스템이 조회하는 **레거시 테이블의 데이터 규격**을 정의한다.

- **목적:** 「시스템 인터페이스 정의서」가 채널 단위(IF-ID·프로토콜·주기·인증)로 정의한 레거시 취득 인터페이스에 대해, 실제로 어떤 **테이블·컬럼·조인키**를 읽는지를 구현 가능한 수준으로 규정한다.
- **범위:** 가공권역 테이블 18종(3~6장 — SAP HANA 10종 + ProSSYS 8종)과 조립권역 테이블 13종(7장 — SAP HANA 8종 + BTS 3종 + 지번 GIS 1종, YDEH060M·YDEH050M 은 가공과 공유) 및 각 키체인. 결과 적재(Hot Data DB·통합 실적)는 대상이 아니다.
- **대상 독자:** 가공·조립권역 판별 서비스 개발자, RFC 모듈·RFC/DB Agent 개발자, 레거시 담당자(한화오션).
- **근거 자료:** `docs/design/dataflow/가공권역_dataflow.drawio` / `docs/design/dataflow/조립권역_dataflow.drawio`(2p 레거시데이터 키체인) / `docs/design/system_architecture/시스템 아키텍쳐.drawio`(취득 구조·Agent 배치) / 「가공권역 실적 판별 기능 정의서」 §4 / 「조립권역 실적 판별 기능 정의서」 §4 / 「시스템 인터페이스 정의서」 §5·§6·부록 C / 「2026-07-29 내업공정실적 가공권역 ProSSYS 소개 및 담당자 미팅」 회의록 / **「Legacy Oracle 테이블·필드 정리」**(ProSSYS·BTS·지번 GIS 65종 컬럼 명세. 출처 — ProSSYS는 `DB_Table Specification V8.1`, BTS는 전사EDA 명세, `GIF_LOTSMALL` 은 예시데이터 기반 추정. Confluence 「Legacy ORACLE 테이블-필드 정리」 페이지 첨부, 2026-08-24).

## 2. 문서 체계와 참조 관계

> **본 문서는 「시스템 인터페이스 정의서」의 하위 문서다.** IF-ID **채번**, 송·수신 시스템, 프로토콜, 연동 주기, 인증, 오류·재처리 정의는 「시스템 인터페이스 정의서」(`docs/인터페이스정의서.md`)를 **유일한 소스**로 한다. 본 문서는 그 인터페이스가 다루는 **데이터 규격**만 정의하며, **본 문서에서 IF-ID를 채번하지 않는다.**

| 문서 | 정의하는 것 | 정의하지 않는 것 |
|---|---|---|
| 시스템 인터페이스 정의서 | IF-ID 채번, 송·수신 시스템, 프로토콜, 주기, 인증, 오류·재처리 | 테이블 컬럼 명세, 조인 조건 |
| **본 문서(레거시 인터페이스 정의서)** | 테이블·컬럼 명세, 키체인·조인 조건, 공정 단계별 수집 지점 | IF-ID 채번, 프로토콜·주기·인증 |
| 권역별 기능 정의서 | 기능ID 단위 판별 규칙 | 위 둘 모두의 상세 |

운영 규칙은 다음과 같다.

1. 본 문서의 각 테이블은 `관련 I/F ID` 로 「시스템 인터페이스 정의서」의 채널을 참조한다. **참조할 IF-ID가 없으면 만들지 말고 `⚠️ 미채번` 으로 남긴다.**
2. 「시스템 인터페이스 정의서」 부록 C(연동 대상 테이블 목록)는 **인벤토리**이고, 컬럼 수준 상세는 본 문서가 보유한다. 테이블이 추가되면 양쪽을 함께 갱신한다.
3. 컬럼·조인 조건이 확정되면 「시스템 인터페이스 정의서」 각 상세의 `데이터 항목` 행에서 본 문서를 참조하도록 유지한다.

## 3. 가공권역 레거시 데이터 소스

**취득 구조** — 판별 서비스는 레거시를 직접 조회하지 않는다. 시스템 아키텍처 다이어그램(`시스템 아키텍쳐.drawio`) 기준 취득 경로는 두 갈래다.

| 경로 | 소재 | 취득 주체 | 방식 | 적재 대상 |
|---|---|---|---|---|
| ① | SAP HANA (Legacy Scheme) | **RFC 모듈**(이 레포 개발) ← **RFC Agent** | RFC Agent가 RFC 모듈을 폴링 (SAP RFC, CMN-IF02) | Hot Data DB |
| ② | Oracle (Legacy Scheme — ProSSYS `AM` · BTS `APNB` · 지번 GIS `SDE`) | **DB Agent** | 폴링 (JDBC, CMN-IF03) | Hot Data DB |

각 권역 실적 판별 서비스는 **Hot Data DB에서 소비**하며(CMN-IF01), 판별 결과의 통합 실적 반영은 Hot Data DB → CDC(Embedded Debezium) → RFC Provider 경로다(본 문서 범위 밖 — 「시스템 인터페이스 정의서」 CMN-IF04 참조). 폴링 주기·인증·오류 처리는 ⚠️ 미확정이다.

> **RFC 모듈:** SAP 소재 테이블의 조회 쿼리를 캡슐화하는 취득 모듈로 **이 레포에서 개발**하며, RFC Agent가 이 모듈을 폴링 호출해 데이터를 수집한다. ⚠️ **모듈 설계는 쿼리 설계 완료 후 본 문서와 「시스템 인터페이스 정의서」에 업데이트한다.**

### 3.2 공정 단계별 수집 지점

「가공권역 실적 판별 기능 정의서」 §3.1의 8단계 공정 흐름에 수집 소스를 대응시킨 것이다.

| 단계 | 공정 | 수집 소스 | 판정 컬럼 | 관련 I/F ID |
|---|---|---|---|---|
| ① | 입고 | STR01H (`PTN_CLSF LIKE 'K%'`) · STY01C | `START_DATE`/`END_DATE` · `ACPT_DATE` | FAB-IF01, FAB-IF14 |
| ② | 선별 | STR01H (`'S%'` 1차 · `'P%'` 2차) · STY01C · STW07M | `START_DATE`/`END_DATE` · `FRST_PICK_ACTL_DATE_1`/`_2` · `SCND_PICK_ACTL_DATE` | FAB-IF01, FAB-IF14 |
| ③ | 불출 | YPWC140M · YPWC111M · ZMMTA001 (SAP) / STW08M · STY01C (ProSSYS) | `ISS_DATE`, `YEDAT` / `PRCS_CLSF='3'`, `ISS_ACTL_DATE` | FAB-IF02, FAB-IF01, FAB-IF14 |
| ④ | 전처리 | ProMES 마킹 상태 | 마킹 상태 `Y`/`N`/`R` | FAB-IF04 (⚠️ 테이블 미확정) |
| ⑤ | 절단 | YPWC310M | `CUT_MFG_FD`, `PRCS_STUS_CODE` | FAB-IF09 |
| ⑥ | 사상 | YPWC820M (+ YPDG002M) | `WORK_DATE` | FAB-IF10, FAB-IF11 |
| ⑦ | 선별 | STW07M (+ STR01H `'S%'`/`'P%'`) | `PRCS_CLSF='3'`(작업완료), `WORK_CLSF` | FAB-IF01 |
| ⑧ | 불출 → 조립 | STW08M (+ STY01C) | `PRCS_CLSF='3'`(불출완료) · `ISS_ACTL_DATE` | FAB-IF01, FAB-IF14 |
| (전개) | 강재 → 도면 → 부재 | YDEH090M · YDEH060M | `DWG_NO`, `PART_NO` | FAB-IF11, FAB-IF12 |
| (집계) | 부재 → 조립품·블록 | YDEH060M → YDEH050M | `ASSY_NO`, `BLK_NO` | FAB-IF12 |

- ①·②·⑦·⑧ 은 **ProSSYS 소스로 확정**되었다(2026-08-24 자료). ProSSYS 는 입고 → 1차 선별 → 2차 선별 → 불출의 4단계를 관리하므로, SAP 기준 3단계(입고·선별·불출)로 병합할 때 `PTN_CLSF` 앞자리(`S`/`P`)를 **선별 1단계로 묶는다**(§5.4).
- **동일 절점에 소스가 둘인 구간이 있다** — ③ 불출은 SAP(`YPWC140M.ISS_DATE`)과 ProSSYS(`STY01C.ISS_ACTL_DATE`) 양쪽에 실적이 존재한다. ⚠️ **우선 소스가 미확정**이다(8장).
- ④ 전처리 판정은 SSY 불출 데이터보다 **마킹 상태 기준이 정확**하다는 담당자 권고가 있다(회의록 5). ⚠️ 최종 채택 여부 미확정.

## 4. 가공권역 테이블 명세

각 테이블은 **속성 표 + 컬럼 표** 2단으로 기술한다. 키 표기는 `PK` 기본키 · `FK` 외래키 · `★` 추적 키체인 핵심이다.

> ⚠️ **SAP HANA 소재 테이블(§4.1~§4.10) 공통 미확정:** 컬럼의 **데이터 타입·길이·NULL 허용 여부·조회 조건(WHERE)·갱신 주기**는 전부 미확정이다. 기준정보·필드 디스크립션 가이드 확보가 선행되어야 한다.
>
> **ProSSYS 소재 테이블(§4.11~§4.18)은 타입·길이가 확보**되어 있다(「Legacy Oracle 테이블·필드 정리」, `DB_Table Specification V8.1` 근거). 따라서 컬럼 표에 `타입(길이)` 열을 함께 둔다. ⚠️ NULL 허용 여부·조회 조건(WHERE)·갱신 주기는 여전히 미확정이다.
>
> 두 계열 모두 감사 컬럼(`RGSR_DATE`/`RGSR_TIME`/`RGSR_USER_ID`/`MNT_DATE`/`MNT_TIME`/`MNT_USER_ID`/`PGM_ID`)은 전 테이블에 공통으로 존재하므로 아래 컬럼 표에서 생략한다 — ⚠️ 증분 조회 기준으로 `MNT_DATE` 를 쓸지는 미확정이다(8장).

### 5.1 조인 경로

강재 실적을 부재 단위로 전개하고 조립품·블록으로 집계하는 표준 경로다. **1~9 는 SAP HANA 소재 경로**, **10~13 은 ProSSYS(Oracle) 소재 경로**다 — 두 계열은 물리 조인이 아니라 업무 키로 연결한다(§5.3).

| 2 | `YPWC111M.PICK_SER_ID = ZMMTA001.STIDNO` | 원자재 불출 → 반출예정 | 핵심 |

### 5.3 조인 시 주의사항

- ⚠️ **`WORK_ORD_NO` 교차 조인 금지** — ProSSYS 의 `WORK_ORD_NO`(`STR01H`·`STW05M`·`STW07M`)는 **ProSSYS 자체 채번**이라 SAP `YPWG411M.WORK_ORD_NO` 와 채번 체계가 다르다. 컬럼명이 같다는 이유로 조인하면 **잘못된 실적이 조용히 매칭된다.** 두 시스템은 업무 키(호선·블록·`ROLL_NO`·일자)로만 연결한다.
- ⚠️ **`ROLL_NO` 단독 키 금지** — 3~4년 주기로 재사용된다(과거 강재가 이미 처리된 상태 전제). 반드시 **기간 한정 조건**과 함께 조회한다(회의록 6). ProSSYS 측에는 `STY01C` 라는 ROLL 마스터가 존재하지만 **마스터가 있다고 해서 재사용 문제가 사라지는 것은 아니다** — `STY01C` 도 같은 `ROLL_NO` 를 재사용한다.
- **관리 단위가 절단 전후로 바뀐다** — 입고~전처리는 자재번호(+`ROLL_NO`), 절단·선별 이후는 `PART_NO`. 하나의 자재번호에 강판이 여러 장 붙는 1:N 관계다.
- ⚠️ **혼재 네스팅** — 한 강판에 여러 블록의 부재가 배치되면 강재 실적을 부재별로 **배분**해야 한다(FAB-F09). 배분 규칙은 미확정이며 `YDEH090M.CUT_REQ_QTY` 가 근거 후보다.
- **집계 시점 차이** — 강재 단계에서 블록은 실시간 확정되나, **조립품은 절단 네스팅 확정 후 소급** 반영된다.
- ⚠️ **겹장 백(Back) 처리** — SSY 불출 데이터는 백 처리를 반영하지 않아 실제와 어긋난다. 마킹 상태(`N` 잔존)로 보정이 필요하다(FAB-F10).
- **판계번호는 조인에 사용하지 않는다** — 불출 일자+순서 조합으로 사실상 불출 순서를 뜻하며, 흐름 확인 목적에는 불필요하다. 자재번호 기준으로 진행하기로 합의하였다(회의록 3).

### 5.4 ProSSYS 작업패턴코드(`PTN_CLSF`) 체계

`STR01H.PTN_CLSF`·`STW05M.CD_PTN` 의 값이며, **앞 1자리가 작업 대분류**다. ProSSYS 실적 판별은 이 앞자리로 절점을 가른다. 근거는 「Legacy Oracle 테이블·필드 정리」의 `작업패턴코드` 시트(52종, 2026-08 김유경 사원 공유 자료)다.

## 6. 물리 테이블명 미확정 소스

회의록에서 존재는 확인되었으나 물리 테이블·컬럼이 확정되지 않은 소스다. 확정 시 4장에 테이블 명세를 추가한다. **SSY(ProSSYS) 스케줄 작업 실적은 2026-08-24 자료로 해소**되어 §3.1·§4.11~§4.18 로 이동했다.

| 소스(논리명) | 역할 | 관련 I/F ID | 상태 |
|---|---|---|---|
| SAP 불출 실적(142 계열) | 판계번호, 선별 강재 고유번호, `ROLL_NO`, 자재번호, 정상 불출 처리 여부 | FAB-IF02 | ⚠️ 142 계열 테이블명 미확정 |

| ProMES 전처리 강재 상태 | ④ 마킹 상태 `Y`/`N`/`R` | FAB-IF04 | ⚠️ 화면 확인 후 쿼리 역추적 예정 |
| ProMES 수기 불출 처리 | 공용재 수기 불출 보완 | FAB-IF06 | ⚠️ 테이블·컬럼 미확정 |
| 설계 일정계획 | 입고·절단·조립 예정일 | FAB-IF05 | ⚠️ 테이블·컬럼 미확정 |

- **인터페이스 계열 선택:** SSY → SAP 인터페이스 원본이 **140 계열**이고 SAP이 재가공한 것이 **142 계열**이다. 활용 시 **142 계열 참조를 권장**한다(회의록 6).
- **SSY DB는 Oracle**이며, 밀사(제철소) B2B 수신 데이터와 SAP 인터페이스 데이터를 별도 Oracle 테이블로 구성해 관리한다. 밀사 데이터도 SAP 특정 테이블에 저장된 후 SSY가 받는 구조이므로 SAP에서도 조회 가능하다(회의록 6).
- **취득 Agent 배정:** ProSSYS 는 Oracle(`AM`) 소재로 확정되어 **DB Agent** 경로다(FAB-IF01·FAB-IF14). SAP 불출 실적(142 계열)·140 계열·설계 일정계획은 **RFC Agent** 경로다. ⚠️ 배정이 남은 것은 **ProMES 계열(FAB-IF04·FAB-IF06)** 뿐이며, 소재 확인 후 §4 명세와 함께 `취득 경로`를 확정한다.

### 7.9 공유 테이블·외부 시스템

- **YDEH060M 부재 마스터** — 컬럼 명세는 **§4.6**을 따른다. 조립 관점 보강: `PART_TYPE_CODE`(K/A/L/M/F)가 송선 **변환 분기** 기준이고, `ASSY_WSTG/NEXT_WSTG`(설계송선)가 변환 원천이다. 관련 기능 — ASM-F05, ASM-F06.
- **YDEH050M 조립품 정보** — 컬럼 명세는 **§4.9**를 따른다. 조립 관점 보강: `ASSY_REQ_QTY`가 카운팅 분모, `ASSY_MFG_SD/FD`가 제작 최초/최종일. 관련 기능 — ASM-F02, ASM-F05.
- **BTS (Oracle, 스키마 `APNB`)** — 블록 운반·위치 추적(ASM-IF03, DB Agent 경로). 물리 테이블 3종이 확정되어 **컬럼 명세는 §7.10~§7.12** 에 있다.
- **지번 GIS (Oracle, 스키마 `SDE`)** — BTS 지번의 해석 기준정보(ASM-IF06). 컬럼 명세는 **§7.13**. ⚠️ 예시데이터 기반 추정분 포함.

- **반입 = 착수 / 반출 = 완료**는 *공정(정반) 관점*의 표현이고, 본 테이블 컬럼은 *운반 관점*이다. 즉 어떤 정반으로의 **운송 완료(`ACTL_TRSP_END_DATE`)가 그 정반의 반입=착수**이고, 그 정반에서의 **운송 시작(`ACTL_TRSP_STRT_DATE`)이 반출=완료**다. 방향을 뒤집지 않도록 주의한다.
- ⚠️ `TPT_TRSP_OBJT_ID` 의 `'호선_블록'` 파싱 규칙(구분자 `_` 고정 여부, 호선 자릿수, 블록 표기 정규화)이 검증되지 않았다. `ZCOT001.PROJ_NOC` 는 `TRIM` 비교가 필요한 4자리 호선이므로 **정규화 규칙을 맞춰야 한다**(§7.8).
- ⚠️ 검사장 이동을 조립 종료로 판정하려면 `ACTL_LANDNO` 가 검사장 지번임을 알아야 한다 — 해석은 `GIF_LOTSMALL`(ASM-IF06, §7.13)에 의존한다.

## 8. 제약사항 및 미확정 항목

**채번**
- ⚠️ **신규 채번분 `FAB-IF09`~`FAB-IF13` 의 연동 주기·인증·오류 처리가 전부 미확정**이다. 테이블·컬럼은 확정되었으나 채널 속성은 후속 협의가 필요하다.
- ⚠️ **`YDEH060M`·`YDEH050M` 은 조립권역과 공유하는 테이블**이다. 가공은 `FAB-IF12`, 조립은 `ASM-IF02` 로 각각 취득하므로 **중복 취득 여부와 `CMN` 공통 채널 승격 필요성** 검토가 필요하다.
- ⚠️ **`ASM-IF06`(지번 GIS)의 접두어 재검토** — 현재는 조립만 쓰지만 선행의장·선행도장도 지번을 쓰게 되면 `CMN` 승격 대상이다.

**스키마**
- ⚠️ **SAP HANA 소재 테이블(§4.1~§4.10, §7.3~§7.8)** 의 컬럼 데이터 타입·길이·NULL 허용 여부가 미확정이다. 기준정보·필드 디스크립션 가이드 확보가 선행되어야 한다. **ProSSYS·BTS 계열(§4.11~§4.18, §7.10~§7.12)은 타입·길이가 확보**되었다(2026-08-24 자료) — 남은 미확정은 NULL 허용 여부다.
- ⚠️ 전 테이블의 **조회 조건(WHERE)·갱신 주기**가 미확정이다.
- ⚠️ **ProSSYS 증분 조회 기준 미확정** — `STR01H` 는 전 강재 이력이라 전량 폴링이 불가하다. `START_DATE`·`END_DATE`·`MNT_DATE` 중 무엇을 증분 커서로 쓸지 확정이 필요하다.
- ⚠️ **`STY01C.FRST_PICK_*_1` 과 `_2` 의 차이 미확정** — 명세상 논리명이 동일하다(§4.17). 재선별 회차로 추정된다.
- ⚠️ **`STY02C.ISS_PLN_DATE`/`_1`/`_2`/`_3` 4개 컬럼의 차수 의미 미확정**(§4.18).
- ⚠️ **가불출(`L*`)·긴급불출(`E*`)의 실적 인정 여부 미확정**(§5.4) — 정상 불출과 동일 취급할지, 별도 플래그로 구분할지 정해야 한다.
- ⚠️ **`GIF_LOTSMALL` 컬럼 명세 미확보**(§7.13) — 예시데이터 1,979행 기반 추정이다. 전사 GIS 담당 확인이 필요하다.
- ⚠️ `YPWC310M.PRCS_STUS_CODE` 의 **코드값 체계**가 미확정이다. (ProSSYS 측 `PTN_CLSF`·`WORK_CLSF`·`PRCS_CLSF`·`ISS_CLSF`·`STUS` 코드 체계는 §4.11~§4.18·§5.4 로 확보되었다.)
- ⚠️ 마킹 상태의 `Y`/`N`/`R` 외 **경고·오류 코드 체계**가 미확정이다.
- ⚠️ `YDEH081M` 의 컬럼이 다이어그램에 전개되어 있지 않다.

**조인**
- ⚠️ 전 **SAP 조인**에 `MANDT` 일치 조건이 필요한지 미확정이다(ProSSYS·BTS 테이블에는 `MANDT` 가 없다).
- ⚠️ **ProSSYS ↔ SAP 연결 키 검증 필요**(§5.1 경로 13) — `ROLL_NO`·`MAT_CODE` 가 SAP 측 값과 동일한지 확인되지 않았다. `WORK_ORD_NO` 는 채번 체계가 달라 **직접 조인이 금지**된다(§5.3).
- ⚠️ **`TPT_TRSP_OBJT_ID` 파싱 규칙 미확정**(§7.11) — `'호선_블록'` 의 구분자·자릿수·블록 표기 정규화를 `ZCOT001.PROJ_NOC`·`BLK_NO` 와 맞춰야 한다.
- ⚠️ 혼재 네스팅 시 강재 실적 **배분 규칙**이 미확정이다(FAB-F09).
- ⚠️ `ROLL_NO` 기간 한정 조회의 **기간 폭**이 미확정이다.

**소재**
- **등재 테이블의 소재가 두 축으로 확정**되었다 — dataflow 테이블은 SAP HANA(경로 ①, CMN-IF02, 2026-08-19 조사), ProSSYS·BTS·지번 GIS 는 Oracle(경로 ②, CMN-IF03, 2026-08-24 자료). ⚠️ 소재가 남은 미확정은 **ProMES 계열(6장)과 설계 일정계획** 뿐이다.
- ⚠️ **RFC 모듈 설계 미확정** — SAP 소재 테이블은 이 레포가 개발하는 RFC 모듈이 쿼리를 캡슐화하고 RFC Agent가 이를 폴링한다. **쿼리 설계 완료 후 모듈 명세를 본 문서에 업데이트한다.**
- **RFC/DB Agent 경유로 확정** — 판별 서비스는 레거시를 직접 조회하지 않고 Agent가 폴링 취득해 Hot Data DB에 적재한다(`시스템 아키텍쳐.drawio`). 단, ⚠️ 폴링 주기·인증·오류 처리는 미확정이다.
- 등재 테이블의 취득 Agent 배정은 **SAP 계열 = RFC 모듈+RFC Agent, Oracle 계열 = DB Agent** 로 확정되었다. ⚠️ 배정이 남은 것은 물리 테이블 미확정 소스(6장 — ProMES·설계 일정계획)뿐이다.

**범위**
- ⚠️ 조립 `YPWS210V`(뷰 추정)와 `ZPPT004_1` 의 **관계·소재가 미확정**이다 — 동일 데이터 계열로 병기 중(§7.3).
- ⚠️ 조립 **송선 변환 5규칙(SZ/SC/N/L/스킵) 쿼리**가 확정 구현으로 검증되지 않았다(정합 ≈95%, 쿼리1 근거).
- ⚠️ `JIG_CODE`(정반코드) ↔ 라이다 설치 정반 **매칭 검증이 필요**하다.
- ⚠️ **③ 불출 절점의 우선 소스 미확정**(§3.2) — SAP(`YPWC140M.ISS_DATE`)과 ProSSYS(`STY01C.ISS_ACTL_DATE`) 양쪽에 실적이 존재한다. 둘을 대사할지, 한쪽을 정본으로 삼을지 정해야 한다.
- ⚠️ **지번 → 샵·정반 매핑 규칙 미확정**(§7.13) — `GIF_LOTSMALL.DESCRIPTION` 이 자연어 표기라 파싱 규칙이 필요하다. `USETYPE`·`PROCESSTYPE`·`WORKPLACECODE` 중 정규 키 선정도 함께 확정한다.
- ⚠️ **`NB103M`(운반 계획) 활용 범위 미확정**(§7.10) — 계획 정보를 신뢰하지 않는다는 원칙과, 실적 누락 대사를 위해 계획을 읽는 것 사이의 경계를 정해야 한다.
- ⚠️ **ProSSYS 비수집 52종의 재검토 트리거 미정**(§3.3) — 특히 차량정보 계열(`STV*`)은 선판계·해양 불출 추적이 필요해지면 대상이 된다.

> **보안:** 레거시 DB 계정·SAP RFC 접속 정보는 본 문서에 기재하지 않는다. 실값은 환경변수로 주입한다(AGENTS.md).
