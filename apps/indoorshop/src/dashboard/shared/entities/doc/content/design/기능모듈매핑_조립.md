## 1. 개요

「조립권역 실적 판별 기능 정의서」의 각 기능(ASM-F01~F10)을 담당 **모듈·헥사고날 레이어** 단위까지 연결한다. 포트/어댑터 **클래스 단위** 상세 매핑은 상세 설계서에서 다룬다.

> **모듈 경계 원칙(AGENTS.md):** 조립권역 로직은 `ot-pipeline-assembly`에 두고 **`ot-core`에만 의존**한다. 다른 `ot-pipeline-*` 모듈은 직접 참조하지 않는다. 4개 zone이 공유하는 판별 엔진(상태머신)은 `ot-core`에 둔다.

### 레포/소유 구분

| 컴포넌트 | 소유 레포 | 비고 |
|---|---|---|
| ot-pipeline-assembly, ot-core | **이 레포**(ocean-inshop-process) | 판별 파이프라인·공통 엔진 |
| **RFC Agent, DB Agent** (레거시 취득: SAP RFC / Oracle·DB) | **이 레포**(ocean-inshop-process) | ISL Agent로 만들지 않고 우리 repo에서 소스 관리 |
| 조립 MQTT Agent (필드 실적 구독) | **별도 ISL repo**(사내 개발) | ISL4 스택. 얇은 구독→Provider 어댑터 |
| 현장 AI Inference·전처리·모델 학습 | **범위 밖**(별도 주체) | 인식 결과만 입력으로 사용 |

> ⚠️ 판별 서비스 ↔ RFC/DB Agent **연동 방식(직접 JDBC vs Agent 경유)** 은 설계 확정 필요.

## 2. 기능-모듈 매핑표

| 기능ID | 담당 모듈 | 헥사고날 레이어 / 구성요소 | 비고 |
|---|---|---|---|
| ASM-F01 필드 인식 수집 | ot-pipeline-assembly | `adapter/in/provider` (ISL4 Agent(별도 ISL repo)가 MQTT 구독 → Provider 진입점 호출) | ⚠️ Provider 프로토콜 미확정 |
| ASM-F02 어셈블리 판별(모드 A) | ot-pipeline-assembly + ot-core | `application/service`(판별 서비스) → ot-core `application/port/in` 판별 유스케이스(`domain/statemachine`) | 규칙: `state-machine-configs/assembly.yml` |
| ASM-F03 라인 카운팅(모드 B) | ot-pipeline-assembly + ot-core | 동일 서비스 + 상태머신(작업장 유형 분기) | `assembly.yml` |
| ASM-F04 매칭 캐스케이드 | ot-pipeline-assembly | `application/service` + `application/port/out` 레거시 게이트웨이(후보 모수 조회) | 하루치/4주 폴백 |
| ASM-F05 계층 집계/롤업 | ot-pipeline-assembly | `application/service` + 레거시 게이트웨이(YDEH 계층) | |
| ASM-F06 송선 변환 매칭 | ot-pipeline-assembly | `domain`(송선 5규칙 변환 — zone 고유 순수 로직) | 프레임워크 비의존 |
| ASM-F07 BTS 트리거 | ot-pipeline-assembly | `adapter/out/legacy` → DB Agent(이 레포) 경유 BTS Oracle 조회 | ⚠️ 연동 방식 확정 필요 |
| ASM-F08 워크오더 귀속 | ot-pipeline-assembly | `application/service` + 레거시 게이트웨이 | ASSY↔W/O N:1 |
| ASM-F09 선행/지연 플래그 | ot-pipeline-assembly | `application/service` | |
| ASM-F10 불일치·누락 노티 | ot-pipeline-assembly | `application/port/out` 결과 통지(ProcessResultNotifier) | ⚠️ 구현 보류(프로토콜 미확정) |
| (공통) 판별 엔진 | ot-core | `domain/statemachine`, `application/port/in` 판별 유스케이스 | 4개 zone 공유 |
| (공통) 결과 저장 | ot-pipeline-assembly | `adapter/out/persistence`(Hot DB 저장) | PostgreSQL |
| (공통) 규칙 외부화 | — | `state-machine-configs/assembly.yml` (`STATE_MACHINE_CONFIG_PATH` 주입) | 재빌드 없이 재시작 반영 |
| (레거시 취득) RFC Agent | **이 레포** | SAP RFC 연동으로 레거시(계획·워크오더 등) 취득 | ISL Agent 아님 |
| (레거시 취득) DB Agent | **이 레포** | Oracle·레거시 DB 연동 취득(BTS 등) | ISL Agent 아님 |

> **참고:** F04(후보 모수)·F05(계층 롤업)·F08(워크오더 귀속)의 "레거시 게이트웨이" 조회는 위 RFC/DB Agent(이 레포)를 경유하거나 직접 접근한다 — 연동 방식은 ⚠️ 설계 확정 필요.
