## 1. 개요

본 문서는 내업 공정실적 자동수집 시스템의 **전체 인터페이스**를 정의한다.

- **목적:** 4개 공정권역(조립·가공·선행의장·선행도장)과 공통 계층이 사용하는 모든 인터페이스의 식별자·송수신 시스템·프로토콜·주기·인증·오류 처리를 한 곳에 정의한다.
- **범위:** OT 계층(실적 판별 서비스·Agent·Provider)과 IT 계층(레거시·통합 실적), 필드 계층(센서·PLC) 사이의 연계 전체. ISL v4 스택 내부 통신(NATS)은 참조로만 다룬다.
- **대상 독자:** 각 권역 판별 서비스 개발자, ISL Agent/Provider 개발자, 인프라 담당자, PM.
- **근거 자료:** 「조립권역 실적 판별 기능 정의서」 / 「가공권역 실적 판별 기능 정의서」 / 「레거시 인터페이스 정의서」 / 「OT Server 인프라 구성 및 CI/CD 설계서」(§2.4 방화벽·포트 체크리스트) / `시스템 아키텍쳐.drawio`(시스템 아키텍처, 물리 배포 다이어그램) / `AGENTS.md`.

### 1.1 단일 소스 원칙

> 인터페이스의 **IF-ID 채번, 송·수신 시스템, 프로토콜, 연동 주기, 인증, 오류·재처리 정의는 본 문서를 유일한 소스로 한다.** 권역별 기능 정의서의 「인터페이스 정의」 장은 요약이며, 상충하는 경우 본 문서를 따른다.

운영 규칙은 다음과 같다.

1. **채번은 본 문서에서만 한다.** 3장 총괄표가 채번 대장이다. 기능 정의서에서 새 IF-ID를 만들지 않는다.
2. **기능 정의서가 보유하는 필드는 4개로 제한한다** — `I/F ID` / `종류` / `대상` / `관련 기능`. 프로토콜 상세·주기·인증·스키마는 기능 정의서에 쓰지 않는다.
3. **양방향 상호참조를 유지한다.** 기능 정의서의 IF-ID는 본 문서를 참조하고, 본 문서 각 상세의 `관련 기능ID` 행은 기능 정의서의 기능ID를 참조한다. 한쪽에만 존재하는 ID는 정합성 검증에서 잡는다.
4. **변경은 동일 커밋으로 처리한다.** 인터페이스 추가·변경 시 ① 본 문서 수정 → ② 영향 권역 기능 정의서 요약표 갱신을 한 커밋에서 함께 반영한다.

## 2. 인터페이스 체계

### 2.1 IF-ID 채번 규칙

```
{권역접두어}-IF{NN}
```

| 접두어 | 대상 |
|---|---|
| `CMN` | 공통 — 2개 이상 권역이 동일 접속 파라미터로 공유하는 물리 채널 |
| `ASM` | 조립권역 |
| `FAB` | 가공권역 |
| `OUT` | 선행의장권역 |
| `PNT` | 선행도장권역 |
| `IPD` | 통합실적대시보드 (IT 조회 시스템) |
| `OTD` | OT 대시보드 (OT 조회 시스템) |
| `KEY` | Key-in 실적 시스템 (IT 입력 시스템) |

- `IPD`·`OTD`·`KEY`는 공정권역이 아니라 **화면을 가진 응용 시스템**이다. 채번·상세 서식은 권역과 동일하게 적용한다.
- `NN`은 권역 내 `01`부터 순차 부여한다.
- **결번을 재사용하지 않는다.** 폐기된 인터페이스는 총괄표에 `폐기` 상태로 남긴다.
- **공통 vs 권역 구분 기준:** 2개 이상 권역이 **동일 접속 파라미터로 공유하는 물리 채널**은 `CMN-IF`로, 권역 고유 데이터셋의 취득·전달은 `{권역}-IF`로 채번한다. 권역 인터페이스 상세에는 `경유 공통 I/F` 행을 두어 상위 채널을 참조한다.

> **참고:** 순수 일련번호(`IF-001` 형식) 대신 권역 접두어 방식을 채택한 이유는, 조립권역 기능 정의서가 이미 `ASM-IF01`~`ASM-IF05`를 사용 중이어서 순수 일련번호로 전환하면 기존 문서의 전면 재번호와 회의 기록과의 단절이 발생하기 때문이다. 접두어가 서로 다르므로 전역 유일성은 이미 만족한다.

### 2.2 시스템 식별자

| 식별자 | 계층 | 설명 |
|---|---|---|
| LiDAR / Vision Sensor | Field | 조립·의장 권역 현장 센서. 인식 결과는 AI Inference Service가 생성 |

| PLC | Field | 선행도장 설비 제어기. Modbus로 ISL Server 직결 |
| MQTT Broker(조립용) | OT · OT-Server-A | EMQX 인스턴스 |
| MQTT Broker(의장용) | OT · OT-Server-B | EMQX 인스턴스 |
| ISL4 Agent | OT | MQTT/Modbus 구독 후 Provider 호출. **별도 ISL repo 소관** |
| 실적 판별 서비스 | OT | `ot-pipeline-{zone}`. 이 레포 소관 |
| RFC 모듈 | OT | SAP 소재 테이블의 조회 쿼리를 캡슐화하는 취득 모듈. **이 레포에서 개발**하며 RFC Agent가 폴링 호출한다. ⚠️ 쿼리 설계 후 모듈 설계 확정 예정 |
| RFC Agent / DB Agent | OT | 레거시 취득 — RFC Agent는 **RFC 모듈을 폴링**해 SAP(Legacy Scheme) 데이터를, DB Agent는 Oracle(Legacy Scheme)을 폴링해 취득하고 Hot Data DB에 적재한다. **이 레포 소관**(ISL Agent 아님) |
| RFC Provider (Embedded Debezium) | OT | Hot Data DB의 변경분을 **CDC**로 캡처해 통합 실적(SAP HANA)으로 반영. dockerized Java Service |
| ISL4 Provider | OT | 판별 결과 전달 |
| Hot Data DB | OT | PostgreSQL |
| ProSSYS | IT | 한화오션 레거시 — 강재 적치/불출 관리. Oracle 스키마 `AM` |
| ProMES | IT | 한화오션 레거시 — 전처리(마킹)·수기 불출. ⚠️ 소재·스키마 미확정 |
| BTS | IT | 한화오션 레거시 — 블록 운반 관리(Block Transportation System). Oracle 스키마 `APNB` |
| 지번 GIS | IT | 한화오션 사내 GIS — 옥포야드 지번(소지번) 폴리곤 기준정보. Oracle 스키마 `SDE`. BTS 지번(`LANDNO`)의 해석 근거 |
| SAP (HANA·Oracle) | IT | 레거시 스킴 및 통합 실적 스킴 |
| 통합 실적 조회 Rest Server | IT | 전자정부 프레임워크. 통합 실적 스킴을 읽어 조회 API로 제공하며, **통합실적대시보드와 Key-in 실적 시스템이 공유**한다 |
| 통합 실적 조회 대시보드 | IT | xplatform. 조회 전용 화면. 「통합실적대시보드 기능 정의서」 소관 |
| Key-in 실적 시스템 | IT | X-Platform 태블릿 앱. 자동수집 실패 건 보완 입력. 「Key-in 실적 시스템 기능 정의서」 소관 |

### 2.3 프로토콜 유형

| 유형 | 설명 |
|---|---|
| MQTT | EMQX Broker 구독/발행. 필드 → OT 실적 수집 경로 |
| Modbus | PLC ↔ ISL Server 직결. **MQTT Broker를 경유하지 않는다** |
| JDBC | 관계형 DB 직접 조회·적재 |
| SAP RFC | SAP 원격 함수 호출을 통한 레거시 취득 |
| Provider | ISL4 Provider 호출을 통한 결과 전달. ⚠️ 실제 전송 프로토콜 미확정 |
| CDC | Debezium 기반 변경 데이터 캡처. Hot Data DB → RFC Provider(Embedded Debezium) 경로 |
| REST | HTTP 기반 조회·저장 API. 통합 실적 조회 Rest Server ↔ 화면 시스템 경로. ⚠️ 엔드포인트·스키마 규격 미확정 |
| NATS | ISL v4 스택 내부 메시징. EMQX와 별개 계층이며 본 시스템의 직접 연계 대상 아님 |

### 2.4 방향·주기 표기

- **방향:** `필드 → OT` / `IT → OT` / `OT → IT` / `OT ↔ IT` / `OT`(OT 내부) / `IT`(IT 내부)
- **주기:** `이벤트`(발생 시 즉시) / `폴링(주기)` / `배치(일 N회)` / `주간`

### 2.5 상태 표기

| 상태 | 의미 |
|---|---|
| 확정 | 근거 문서로 확인된 인터페이스. 근거를 비고에 남긴다 |
| ⚠️ 미확정 | 존재는 확인되었으나 프로토콜·대상·주기 중 하나 이상이 미정 |
| 폐기 | 더 이상 사용하지 않음. 채번은 회수하지 않는다 |

## 10. 공통 규약

### 10.1 인증·자격증명 관리

- DB 계정·SAP RFC 연동 정보 등 자격증명은 **환경변수로 주입**하며 본 문서에는 플레이스홀더만 기재한다.
- `.env.*.example`만 커밋하고 실값은 `.gitignore` 처리한다.
- 자격증명·한화오션 내부 비공개 자료를 문서·코드·Agent 컨텍스트에 인라인하지 않는다.

### 10.2 오류 처리·재처리

- DB·Broker 연결은 기동 순서를 가정하지 않고 재시도로 견고성을 확보한다(`hikari.initialization-fail-timeout: -1` 등).
- ⚠️ 재시도 횟수·백오프 정책, 실패 건 격리(Dead Letter) 방식은 미확정이다.
- ⚠️ 멱등성 키 체계는 미확정이다. 가공권역의 ROLL_NO는 3~4년 주기로 재사용되므로 단독 키로 사용할 수 없다.

### 10.3 로깅·추적

- ⚠️ 인터페이스 호출 추적 ID(correlation ID) 체계 미확정.

### 10.4 타임존·문자셋

- ⚠️ 타임존 기준(KST vs UTC)과 일시 표기 형식 미확정. 레거시 원천의 표기와 정합을 맞춰야 한다.
- ⚠️ 문자셋 규약 미확정.

## 12. 제약사항 및 미확정 항목

**프로토콜·연동 방식**
- ⚠️ **OT-Server ↔ ISL Server/통합 실적 전달 프로토콜·포트 미확정**(CMN-IF04, ASM-IF04, FAB-IF08). ISL4 표준 인터페이스 확인 후 갱신이 필요하다.
- ⚠️ **CDC(Embedded Debezium) 상세 규격 미확정**(CMN-IF04) — 캡처 대상 테이블·스냅샷 정책·재전송 규칙, SAP RFC 전송 함수·포트.
- ⚠️ **RFC 모듈 설계 미확정**(CMN-IF02) — SAP 소재 테이블의 쿼리를 캡슐화하는 모듈로 이 레포에서 개발하며 RFC Agent가 폴링한다. **쿼리 설계 완료 후 모듈 명세·인터페이스 상세를 업데이트한다.**
- ⚠️ **Provider 엔드포인트 프로토콜**(REST/RPC) 미확정 — `{Zone}ProviderEndpoint`는 포트만 정의되어 있다.
- ⚠️ **공정 태그 Provider 역할** 확정 필요(인프라설계서 §8).
- ⚠️ **통합 실적 조회 Rest Server의 REST API 규격 전면 미확정**(IPD-IF01, KEY-IF01) — 엔드포인트, 요청·응답 스키마, 페이징·정렬 전달 방식, 인증, 오류 코드.
- ⚠️ **Key-in 실적의 저장 경로 미확정**(KEY-IF01) — `시스템 아키텍쳐.drawio`는 `Rest Server → Key-In 실적 webapp` 방향만 표기한다. 확정 실적이 어느 저장소에 어떤 경로로 반영되는지(Rest Server 경유 여부, 통합 실적 스킴 직접 반영 여부) 확정이 필요하다.
- ⚠️ **자동수집 실패 판정의 주체·시점·기준 미확정**(KEY-IF01) — Key-in 화면에 표시할 "실패 건"을 어느 시스템이 어떤 조건으로 확정하는지 정의가 필요하다.
- **가공·조립 dataflow 등재 테이블의 소재는 SAP HANA로 확인**되었다(2026-08-19 협의) — FAB-IF02/03/09~13·ASM-IF02의 경유가 CMN-IF02(RFC 모듈+RFC Agent)로 확정되었다.
- **Oracle 축 소재도 확정**되었다(2026-08-24 「Legacy Oracle 테이블·필드 정리」) — ProSSYS(`AM`, FAB-IF01·FAB-IF14)·BTS(`APNB`, ASM-IF03)·지번 GIS(`SDE`, ASM-IF06)가 모두 CMN-IF03(DB Agent) 경유로 확정되었다. ⚠️ 소재가 남은 미확정은 **ProMES 계열(FAB-IF04/06)** 뿐이다.
- ⚠️ **ProSSYS 증분 조회 조건 미확정**(FAB-IF01) — `STR01H` 는 전 강재 이력 테이블이라 전량 폴링이 불가하다. `START_DATE`/`END_DATE`/`MNT_DATE` 중 무엇을 증분 기준으로 쓸지 확정이 필요하다.
- ⚠️ **ProSSYS ↔ SAP 강재 연결 키 검증 필요** — `ROLL_NO`·`MAT_CODE` 가 SAP 자재번호·`ROLL_NO` 와 동일 값인지 확인되지 않았다. `WORK_ORD_NO` 는 채번 체계가 달라 **직접 조인이 금지**된다(FAB-IF01 비고).
- ⚠️ **지번 → 샵·BAY 매핑 규칙 미확정**(ASM-IF06) — `GIF_LOTSMALL.DESCRIPTION` 이 자연어 표기(`GBS 남쪽 조립검사 7번 셀터/선행의장-07`)라 파싱·매핑 규칙 정의가 필요하다.

**배치**
- ⚠️ **RFC/DB Agent 물리 배치 상이** — 물리 배포 다이어그램은 RFC Agent·DB Agent·RFC Provider를 Hot Data DB 서버에 배치하나 AGENTS.md는 ISL Server로 규정한다(`시스템 아키텍쳐.drawio` 물리 배포 페이지에서 재확인).

**규격**
- ⚠️ **운영 MQTT 토픽 명명 규칙 미확정**(부록 A).
- ⚠️ **운영 메시지 페이로드 스키마 미확정**(부록 B). 인용한 Envelope의 원본 설계문서가 레포에 부재하다.
- ⚠️ **DB 테이블 컬럼·타입·길이 미확정**(부록 C).
- ⚠️ **오류 코드 체계 미확정**(부록 D).
- ⚠️ **재시도·백오프·Dead Letter 정책 미확정**(§10.2).
- ⚠️ **멱등성 키 체계 미확정**(§10.2). 가공권역 ROLL_NO는 3~4년 주기 재사용으로 단독 키 사용이 불가하다.
- ⚠️ **추적 ID·타임존·문자셋 규약 미확정**(§10.3, §10.4).

**범위**
- ⚠️ **선행의장·선행도장 권역 인터페이스는 골격만** 등록되었다. 해당 권역 기능 정의서 작성 시 확장한다.
- ⚠️ **MQTT 인증 방식 미확정**(ASM-IF01, OUT-IF01).
- ⚠️ **가공권역 신규 채번분(FAB-IF09~FAB-IF13)의 연동 주기·인증·오류 처리가 전부 미확정**이다. 테이블·컬럼은 「레거시 인터페이스 정의서」로 확정되었으나 채널 속성은 후속 협의가 필요하다.
- ⚠️ **YDEH060M·YDEH050M은 가공(FAB-IF12)과 조립(ASM-IF02)이 공유하는 테이블**이다. 중복 취득 여부와 `CMN` 공통 채널 승격 필요성을 검토해야 한다(§2.1 공통 vs 권역 구분 기준).
- ⚠️ **IPD-IF01·KEY-IF01은 「통합 실적 조회 Rest Server」를 공유한다.** 동일 접속 파라미터를 쓰는지는 API 규격 확정 전까지 판정할 수 없어 이번에는 시스템별로 채번하였다. 규격 확정 시 `CMN` 공통 채널 승격을 검토해야 한다(§2.1).
- ⚠️ **OT 대시보드(`OTD`) 인터페이스는 미채번**이다. 아키텍처상 4개 실적 판별 서비스와 Hot Data DB를 직접 받는 OT 계층 시스템이나, 기능 정의서가 아직 작성되지 않았다.

## 13. 용어 정의

| 용어 | 설명 |
|---|---|
| I/F(인터페이스) | 시스템 간 데이터를 주고받는 논리적 연계 단위. 본 문서의 채번 대상 |
| IF-ID | 인터페이스 식별자. `{권역접두어}-IF{NN}` 형식 |
| 경유 공통 I/F | 권역 인터페이스가 사용하는 상위 공통 물리 채널 |
| EMQX | MQTT Broker 구현체. 조립용·의장용 2개 인스턴스로 분리 운영 |
| NATS | ISL v4 스택 내부 메시징 구현체. EMQX와 별개 계층 |
| ISL4 Agent | MQTT/Modbus를 구독해 Provider를 호출하는 벤더 컴포넌트. 별도 ISL repo 소관 |
| Provider | 판별 결과를 상위 계층으로 전달하는 ISL4 구성요소 |
| CDC | Change Data Capture — DB 변경분을 실시간 캡처하는 방식. Hot Data DB → RFC Provider 경로에 사용 |
| Embedded Debezium | RFC Provider에 내장된 CDC 구현체. Hot Data DB(PostgreSQL)의 변경 이벤트를 구독한다 |
| RFC 모듈 | SAP 소재 테이블 조회 쿼리를 캡슐화한 취득 모듈. 이 레포 개발, RFC Agent가 폴링 호출. ⚠️ 쿼리 설계 후 확정 |
| RFC Agent / DB Agent | SAP RFC·레거시 DB에서 데이터를 취득하는 컴포넌트. **이 레포 소관** |
| Hot Data DB | OT망의 PostgreSQL. 판별 중간·결과 저장소 |
| 통합 실적 | IT망의 SAP HANA에 적재되는 최종 실적 |
| Modbus | 선행도장 PLC ↔ ISL Server 직결 프로토콜. MQTT를 경유하지 않음 |
