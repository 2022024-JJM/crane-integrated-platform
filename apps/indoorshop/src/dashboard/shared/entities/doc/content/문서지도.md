## 3. 디렉토리 규약

새 문서는 유형에 따라 아래 폴더에 둔다. 최상위 `docs/`에는 이 문서(`문서지도.md`)만 둔다.

| 유형 | 폴더 | 파일명 |
|---|---|---|
| 규칙·가이드 | `guide/` | 자유 (한글) |
| 기능 정의서 | `spec/` | `기능정의서_{권역 또는 시스템}.md` |
| 인터페이스 정의서·태그 목록 | `interface/` | 정의서명 그대로. 엑셀 동기본은 `interface/export/{이름}_v{버전}.xlsx` |
| 아키텍처·데이터플로우·모듈 매핑·화면 설계 | `design/` 하위 (`system_architecture/`, `dataflow/`, `uiux/`) | 유형별 규칙 (`design/uiux/README.md` 참조) |
| 개선 제안 | `prd/` | `PRD_{슬러그}.md` |
| 구현 계획·기록 | `plan/{모듈}/` | `plan-{슬러그}.md` |
| 회의록 | `회의록/` | `{YYYY-MM-DD}_{제목}.md` |
| 이미지·첨부 | `assets/화면설계/{시스템}/` · `회의록/assets/{슬러그}/` | `{PFX}-S##_{슬러그}.png` |

- 중간 산출물(초안·변환 결과·스크래치)은 `.work/`(gitignore)에 두고 커밋하지 않는다.
- 문서 간 참조는 낫표 제목(「인터페이스 정의서」)과 레포 기준 경로(`docs/interface/인터페이스정의서.md`)를 함께 쓴다. 문서 안 상대 링크는 자기 폴더 기준이다(예: `spec/`에서 캡처는 `../assets/화면설계/…`).
- OT 대시보드(`apps/ot-dashboard/`)의 인앱 문서 뷰어(`/docs`)는 `guide/`·`spec/`·`interface/`·`prd/`·`design/`의 Markdown과 이 문서를 번들에 담아 보여 준다. `회의록/`·`plan/`은 내지 않는다.
- **파일명:** 공백을 쓰지 않는다(단어 사이는 `_`). 링크·스크립트·셸에서 깨진다. 기존 예외는 `design/system_architecture/시스템 아키텍쳐.drawio` 하나 — 「인터페이스 정의서」 등이 수십 곳에서 파일명으로 인용하므로 다음 인터페이스 정의서 개정 때 참조와 함께 바꾼다.
- **문서 등급:** 정식 문서(`spec/`·`interface/`·`design/`의 설계서·`guide/`의 가이드)는 house-style 머리말(제목 2줄·버전·작성·소속)과 변경 이력이 필수다. 작업 문서(`prd/`·`plan/`·`design/uiux/` 설계서·`회의록/`)는 제목과 상태 한 줄로 충분하다. 이 문서의 표에서 '버전' 열이 있는 문서가 정식 문서다.
- **폐기 문서:** 대체된 문서는 머리에 `⚠️ SUPERSEDED (날짜) — 대체 문서 링크` 블록을 두고 이 문서의 표에 **폐기**로 표기한다. 색인에서 내린 문서는 레포에서 삭제한다(이력은 git에 남는다).
- **규칙 단일 소스:** 규칙은 `AGENTS.md`에만 쓴다. `guide/`는 절차·설명을 담고, 규칙이 필요한 자리에는 `AGENTS.md`의 절을 링크한다.
- 정식 설계 문서의 서식은 `.claude/skills/functional-spec/references/house-style.md`를 따른다.

## 4. 채번·단일 소스 규칙

| 식별자 | 채번 권한 | 다른 문서에서는 |
|---|---|---|
| IF-ID (`CMN-IF##`, `FAB-IF##` …) | `interface/인터페이스정의서.md` §3 총괄표 | 참조만. 기능 정의서 §7/§9 요약표는 거울 |
| 화면 ID (`OTD-S##`, `IPD-S##`, `KEY-S##`) | 해당 `spec/기능정의서_*.md` §4 화면 목록 | 화면 설계서는 `(안)`을 붙여 제안 |
| 기능 ID (`{PFX}-F##`) | 해당 `spec/기능정의서_*.md` §7 기능 목록 | `design/기능모듈매핑_*.md`가 참조 |
| 화면 설계 미확정 번호 (`[미확정 n]`) | `.claude/agents/uiux-context/prd.md` §10 | 설계서는 번호만 참조 |

⚠️ **화면 ID 체계 두 벌 `[확인 필요]`** — 기능 정의서는 `OTD-S01~S04`를 채번했으나 Figma 와이어프레임·화면 설계 PRD는 현 구현을 `OTD-S00~S12`로 부른다. 정본 결정 전까지 신규 설계서의 ID는 `(안)`이다. 상세는 `design/uiux/화면목록.md`.
