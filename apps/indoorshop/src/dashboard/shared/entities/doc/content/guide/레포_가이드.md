# 레포 구조 및 Claude Code 작업 가이드

> [!NOTE]
> 규칙의 정본은 [`AGENTS.md`](../../AGENTS.md), 문서 색인은 [`문서지도.md`](../문서지도.md)다. 이 문서는 두 가지만 다룬다. 레포가 어떻게 생겼는지, Claude Code로 어떻게 일하는지.

## 1. 레포 구조

```
ocean-inshop-process/
├── AGENTS.md / CLAUDE.md        # 레포 공통 규칙 / Claude Code 래퍼
├── .claude/                     # 스킬 3 · 서브에이전트 1 · settings.json (레포 공통)
├── services/                    # Java 루트 — Gradle 멀티모듈
│   ├── AGENTS.md / CLAUDE.md    # Java 모듈 규칙
│   ├── ot-core/                 # 상태 머신 엔진 라이브러리
│   ├── ot-pipeline-{zone}/      # 가공·조립·선행의장·선행도장 실적 판별 서비스
│   ├── legacy-agent-simulator/  # 개발 도구 (운영 배포 아님)
│   └── state-machine-configs/   # zone별 판별 규칙 YAML (정본)
├── apps/                        # 프론트엔드 루트
│   ├── AGENTS.md / CLAUDE.md    # 프론트엔드 규칙
│   └── ot-dashboard/            # OT 대시보드 (React + Vite)
├── deploy/                      # 서버별 docker-compose · initdb · dev 스크립트
└── docs/                        # 설계 문서 — 색인 docs/문서지도.md
```

| 원칙 | 내용 |
|---|---|
| 1단계 디렉토리 = 빌드 루트 | `services/`는 Gradle 루트, `apps/`는 프론트엔드 루트. 프로그램은 그 아래 하나씩 |
| 망 구분은 이름 접두 | OT망 `ot-*`, IT망 `it-*`. 디렉토리로 나누지 않는다 |
| `docs/`·`.claude/`는 루트에 하나 | 프로그램별로 분리하지 않는다 |
| 규칙은 세 겹 | 루트 `AGENTS.md`(공통) + `services/AGENTS.md`(Java) + `apps/AGENTS.md`(프론트). 하위 디렉토리에서 작업하면 해당 문서가 추가로 적용된다 |

프로그램 목록과 각 프로그램의 규칙·문서는 [`AGENTS.md` 「프로그램 인벤토리」](../../AGENTS.md#프로그램-인벤토리)에 있다.

## 2. Claude Code 작업 가이드

### 2.1 시작

레포 루트에서 `claude`를 실행한다. 하위 디렉토리에서 실행해도 `CLAUDE.md`를 루트까지 올라가며 읽으므로 규칙은 같다. 커밋된 `.claude/settings.json`으로 git 읽기·gradlew·npm lint/test/build는 확인 없이 실행된다. 개인 설정은 `.claude/settings.local.json`(gitignore).

### 2.2 작업 요청

대상 프로그램과 할 일을 명시한다. 에이전트는 `AGENTS.md` 인벤토리에서 프로그램을 찾아 해당 문서를 먼저 읽는다.

```
조립 zone(ot-pipeline-assembly)에 LiDAR 체류 이벤트 판별을 추가하려고 한다.
먼저 docs/spec/기능정의서_조립.md §3.2를 읽고 services/state-machine-configs/assembly.yml에
필요한 전이를 정리해 달라. 코드는 아직 쓰지 않는다.
```

### 2.3 문서 작업은 스킬

| 스킬 | 용도 |
|---|---|
| `/confluence-minutes` | Confluence 첨부 회의록을 `docs/회의록/`로 반입 |
| `/functional-spec` | 기능정의서 작성·갱신 (`docs/spec/`) |
| `/interface-spec` | 인터페이스정의서 추가·확정·정합성 검사 (`docs/interface/`) |

### 2.4 서브에이전트 브리핑

서브에이전트는 대화 맥락을 상속하지 않는다. 넘길 때 아래 양식으로 적는다 (정본은 `CLAUDE.md` 「서브에이전트 브리핑 틀」).

```
목표: 도장 공정 화면에 설비 가동률 카드 추가
범위: apps/ot-dashboard/src/processes/painting/ 안에서만
먼저 읽을 것:
  - apps/AGENTS.md 「OT 대시보드」 절
  - docs/spec/기능정의서_OT대시보드.md §6.3
이미 결정된 것: 데이터는 mock, 카드 위치는 우상단
하지 말 것: shared/ 수정, 새 IF-ID 채번
보고: 변경 파일 목록, 남은 [확인 필요]
```

### 2.5 커밋·PR

테스트 없는 PR은 머지 대상이 아니다. 커밋은 `type(scope) : 설명`, 브랜치는 `feature/{모듈}-{설명}`, `AGENTS.md` 변경 PR은 제목에 `[AGENTS.md]`. `main` 직접 push 금지. 에이전트 산출물은 리뷰 없이 머지하지 않는다.

### 2.6 로컬 실행

| 작업 | 명령 |
|---|---|
| Java 빌드 | `cd services && bash gradlew build` |
| 대시보드 | `cd apps/ot-dashboard && npm run dev` · `npm run lint` · `npm test` |
| 전체 기동 | `./deploy/scripts/dev-up.sh` |
| 가공 E2E | [`deploy/README.md`](../../deploy/README.md) 「가공 PoC E2E 검증」 |
