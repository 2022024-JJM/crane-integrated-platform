# 전체 현황 공정존·베이 드릴다운 개선 PRD

- 문서 상태: Draft
- 작성일: 2026-08-26
- 대상 앱: `web-dashboard`
- 1차 구현 범위: 전체 현황 대시보드와 조립 공정

## 1. 배경과 문제

현재 `/` 대시보드는 제목 `전체 현황`, 부제 `4개 공정존의 수집 상태` 아래 옥포 야드 지도와 공정존 카드 4개를 제공한다. 사용자는 공정 카드 또는 지도에서 공정을 강조하고, 공정 카드 안의 공장이나 지도 위 공장을 선택할 수 있다. 그러나 공장 선택 뒤 표시되는 정보는 지번 수, 면적, 옥내·옥외 수, 분류 구성뿐이며 다음 단계인 작업 위치를 선택하거나 해당 위치의 공정 현황으로 이동할 수 없다.

조립 모듈에는 이미 공장 목록, 공장 전체 정반 화면, 정반 상세 화면이 있고 다음 라우트를 사용한다.

| 수준 | 기존 라우트 | 의미 |
|---|---|---|
| 조립 공장 목록 | `/zones/assembly` | 조립 공장 선택 |
| 조립 공장 현황 | `/zones/assembly/:factoryId` | 공장 내 정반 현황 및 센서 퓨전 |
| 조립 정반 현황 | `/zones/assembly/:factoryId/:locationId` | 선택 정반의 LiDAR 인식 현황 |

현재 조립 `Location`은 베이(정반 단위 작업 위치)를 나타내며 `id`, `factoryId`, `name`, `status`, `workCntr`와 선택적인 `projNo`, `blkNo`, `yardLots`를 가진다. 이 중 `yardLots`는 야드 지도와 조립 정반을 잇는 유일한 연결 키로 정의돼 있으나 실제 `WORK_CNTR ↔ LOT` 운영 마스터는 아직 확정되지 않았고 현재 데이터는 목업이다.

## 2. 사용자 결과

생산 현황 사용자는 전체 현황에서 화면의 목적과 조작 순서를 바로 이해하고, 지도의 공정 영역을 선택한 뒤 해당 공정의 공장과 작업 위치를 단계적으로 선택하여 별도 탐색 없이 위치별 현황 화면에 도달할 수 있어야 한다.

조립의 목표 흐름은 다음과 같다.

```mermaid
flowchart LR
    A[전체 현황] --> B[공정 선택: 조립]
    B --> C[조립 공장 선택]
    C --> D[베이·정반 목록 표시]
    D --> E[베이·정반 선택]
    E --> F[기존 조립 정반현황 화면]
```

## 3. 목표와 비목표

### 목표

1. `전체 현황`과 `4개 공정존의 수집 상태`가 지도와 드릴다운 기능의 목적을 함께 설명하도록 정보 위계를 개선한다.
2. 지도 및 우측 패널에서 공정 → 공장 → 작업 위치의 현재 선택 단계와 다음 행동을 명확히 보여준다.
3. 조립 공장 선택 시 해당 공장의 베이(정반)를 선택할 수 있게 한다.
4. 조립 베이 선택 시 기존 정반현황 라우트로 이동한다.
5. 공통 대시보드가 `processes/assembly`를 직접 import하지 않고 레지스트리 경계를 유지한다.

### 비목표

- 기존 조립 정반현황의 LiDAR 3D/2.5D 표현, 판별 로직 또는 데이터 시각화를 재설계하지 않는다.
- 생산 좌표, 상태 임계값, 운영 식별자 또는 백엔드 전달 프로토콜을 새로 정의하지 않는다.
- 가공·선행의장·선행도장에 조립의 `베이/정반` 개념을 강제로 적용하지 않는다.
- 공정 모듈 간 직접 import 또는 `shared`에서 `processes/**` 직접 import를 허용하지 않는다.
- 목업 `yardLots` 연결을 운영 마스터로 간주하지 않는다.

## 4. 용어와 표시 원칙

| 용어 | 이 문서의 의미 | 근거/제약 |
|---|---|---|
| 공정존 | 가공, 조립, 선행의장, 선행도장 | 기존 `Zone` 및 대시보드 카드 |
| 공장 | 지도 지번이 묶인 시설이자 공정 하위 선택 단위 | 현재 야드 지번 fixture와 공장 목록 |
| 작업 위치 | 공정별 상세 진입 단위의 공통 UI 명칭 | 공정마다 실제 명칭과 식별자가 다를 수 있음 |
| 베이(정반) | 조립의 작업 위치 | 기존 `Location`, 화면에서는 사용자가 익숙한 명칭을 병기 |
| 정반현황 | 조립의 기존 `/zones/assembly/:factoryId/:locationId` 화면 | 새 상세 화면을 만들지 않고 기존 라우트 재사용 |

공통 UI는 `작업 위치`라는 상위 개념을 사용하되, 조립 데이터가 제공하는 표시 명칭은 `베이(정반)` 또는 저장소에서 이미 쓰는 `정반`을 사용한다. 최종 한글 표기 통일은 제품 책임자 확인이 필요하다.

## 5. 정보 구조와 상호작용

### 5.1 페이지 제목 영역

- 주 제목은 현재 라우트의 범위를 유지하여 `전체 현황`으로 둔다.
- 부제는 단순한 상태 설명을 넘어 사용 가능한 동작을 알려야 한다. 제안 문구는 `4개 공정존의 수집 상태를 확인하고 공장·작업 위치별 현황으로 이동합니다.`이다.
- 문구는 공통 로케일의 `dashboard.title`, `dashboard.subtitle`에서 관리하며 한국어와 영어를 함께 갱신한다.
- 최종 문구는 제품 카피 승인 대상이며, 승인 전에는 PRD 제안으로만 취급한다.

### 5.2 선택 단계

우측 통합 패널은 사용자가 현재 어디까지 선택했는지 다음 순서로 표현한다.

1. 공정존
2. 공장
3. 작업 위치(조립: 베이/정반)

- 아직 선택하지 않은 하위 단계는 비활성 안내문을 표시한다.
- 상위 선택이 바뀌면 그 아래 선택은 즉시 초기화한다.
- 지도 공장 클릭과 패널 공장 클릭은 동일한 선택 상태를 사용한다.
- 선택한 공정·공장·작업 위치는 색만이 아니라 이름, 선택 표시, `aria-current` 또는 `aria-pressed`로도 구분한다.
- 공정 카드의 접기/펴기와 지도 스포트라이트는 현재처럼 별도 동작으로 유지하되, 공정 선택 후 해당 카드가 펼쳐져 다음 선택을 보여준다.

### 5.3 공장과 작업 위치 선택

- 공정 선택 시 그 공정에 속한 공장 목록을 표시하고 지도 카메라는 기존처럼 해당 공정 범위에 맞춘다.
- 공장 선택 시 지도 카메라는 기존처럼 공장 범위에 맞추고, 공장 상세 카드에 `작업 위치` 섹션을 추가한다.
- 조립 공장은 조립 모듈이 제공한 베이(정반) 목록을 표시한다. 각 항목의 필수 표시는 이름과 정반코드(`workCntr`)이다.
- `status`, `projNo`, `blkNo`는 값이 있을 때만 보조 정보로 표시한다. 값이 없을 때 공백이나 가짜 기본값을 만들지 않고 `정보 없음`을 표시하거나 보조 행 자체를 생략한다.
- 상태 의미는 기존 `LocationStatus`(`occupied | empty | unknown`)만 사용한다. 별도 건강 색이나 위험 판단을 만들지 않는다.
- 작업 위치 항목을 선택하면 지도에서 연결 가능한 지번을 강조하고, 같은 항목을 활성화하거나 명시적 `정반현황 열기` 동작을 수행하면 해당 상세 라우트로 이동한다.
- 단일 클릭 즉시 이동 여부는 모바일과 키보드 사용성을 고려해 다음 기본안을 적용한다: 항목 한 번 클릭/포커스는 선택 및 위치 강조, 항목 내부의 `정반현황 열기` 링크 또는 선택 항목 재활성화는 상세 이동. 제품 책임자가 즉시 이동을 선호하면 구현 전에 확정한다.
- 공장 전체 현황으로 이동하는 기존 라우트도 `공장 현황 열기` 보조 동작으로 유지한다.

### 5.4 지도 표현

- 작업 위치에 유효한 지도 연결 키가 있으면 그 지번만 강하게 강조하고, 같은 공장의 나머지 지번은 문맥이 남도록 낮은 강조로 유지한다.
- 연결 키가 없거나 지도 데이터에 존재하지 않으면 목록 선택과 상세 이동은 허용하되 지도에는 `지도 위치 정보 없음`을 표시한다.
- 여러 지번에 걸친 정반은 모든 연결 지번을 하나의 선택으로 강조한다.
- 선택된 지번이 현재 화면 밖이면 해당 범위로 카메라를 맞추되 사용자의 `prefers-reduced-motion` 설정에서는 즉시 이동한다.
- 지도만으로 제공되는 핵심 정보가 없도록 우측 목록에 동일한 공정·공장·작업 위치와 이동 동작을 제공한다.

## 6. 기능 요구사항

### FR-1. 제목과 안내 문구

대시보드는 `전체 현황`을 최상위 제목으로 유지하고, 부제에서 4개 공정존의 수집 상태 확인과 공장·작업 위치 드릴다운 가능성을 함께 안내해야 한다.

### FR-2. 계층 선택 상태

대시보드는 공정, 공장, 작업 위치 선택을 하나의 일관된 상태로 관리해야 하며 상위 선택 변경 시 하위 선택을 제거해야 한다. 뒤로가기 동작이 예상 가능하도록 상세 화면 이동은 기존 React Router 라우트를 사용해야 한다.

### FR-3. 모듈 소유 작업 위치 제공

공통 대시보드는 공정별 작업 위치 데이터나 상세 URL 규칙을 하드코딩하지 않아야 한다. `ProcessModule.provides`와 `processRegistry`를 확장하여 공정 모듈이 다음 정보를 비동기로 제공하게 한다.

```ts
interface ProcessMapLocation {
  id: string
  parentFacilityKey: string
  displayName: string
  locationCode?: string
  statusLabelKey?: ParseKeys
  yardLotCodes?: string[]
  detailPath: string
}

interface ProcessMapDrilldownProvider {
  locationNounKey: ParseKeys
  fetchLocations(parentFacilityKey: string): Promise<ProcessMapLocation[]>
  facilityPath?: (parentFacilityKey: string) => string
}
```

위 계약은 구현 설계의 출발점이며 이름은 코드 리뷰에서 조정할 수 있다. 반드시 지켜야 하는 의미는 다음과 같다.

- 공정 모듈이 작업 위치 명칭, 조회, 상세 경로를 소유한다.
- `shared`는 조립의 `Location` 타입이나 API를 직접 import하지 않는다.
- `detailPath`는 앱 내부 절대 경로이며 대시보드는 이를 조합하거나 추론하지 않는다.
- 생산 식별자를 표시명으로 대체하지 않는다.
- provider가 없는 공정은 오류가 아니라 `작업 위치 상세 미제공` 상태로 처리한다.

### FR-4. 조립 어댑터

조립 모듈은 기존 `fetchLocations(factoryId)`와 `Location`을 공통 드릴다운 계약으로 변환해야 한다. 변환은 `processes/assembly` 내부에서 수행한다.

| 공통 필드 | 조립 원천 | 규칙 |
|---|---|---|
| `id` | `Location.id` | 그대로 사용 |
| `parentFacilityKey` | `Location.factoryId` | 지도 공장과 조립 `Factory.id` 연결 후 사용 |
| `displayName` | `Location.name` | 그대로 표시 |
| `locationCode` | `Location.workCntr` | 값이 있을 때 정반코드로 표시 |
| 상태 | `Location.status` | 기존 enum의 번역 키로 변환 |
| `yardLotCodes` | `Location.yardLots` | 선택적; 없으면 지도 강조 없음 |
| `detailPath` | 기존 라우트 | `/zones/assembly/{factoryId}/{locationId}` |

현재 지도 공장명과 조립 `Factory.id`는 동일 키가 아니다. 공장 선택을 `factory.name` 문자열로 조립 API에 넘기지 말고, 조립 모듈이 소유하는 명시적 매핑을 제공해야 한다. 운영 매핑이 확정되기 전에는 fixture 매핑을 `non-production`으로 표시한다.

### FR-5. 로딩·빈 값·오류·오래된 데이터

- 로딩: 선택된 공장 아래 작업 위치 스켈레톤 또는 스피너를 표시하고 기존 목록을 다른 공장의 데이터로 오인하게 남겨두지 않는다.
- 빈 값: `등록된 작업 위치가 없습니다.`와 공장 현황 이동 동작을 표시한다.
- 조회 오류: `작업 위치를 불러오지 못했습니다.`와 재시도 동작을 제공한다. 지도와 다른 공정 선택은 계속 사용할 수 있어야 한다.
- 지도 연결 없음: 목록과 상세 이동은 유지하고 위치만 `지도 위치 정보 없음`으로 표시한다.
- 오래된 데이터: 현재 계약에는 갱신시각과 stale 기준이 없으므로 임의 경고색을 사용하지 않는다. 추후 원천이 `updatedAt`과 stale 기준을 제공할 때 별도 요구로 추가한다.
- provider 없음: 해당 공정은 기존 공정 화면 링크를 유지하며 `작업 위치 상세는 준비 중입니다.`를 표시한다.

### FR-6. 접근성 및 반응형

- 공정, 공장, 작업 위치를 키보드만으로 순서대로 선택하고 상세 화면을 열 수 있어야 한다.
- 선택, 펼침, 로딩, 오류 상태를 스크린리더가 인식할 수 있어야 한다.
- 모든 포커스 가능 항목에 가시적 포커스 링을 제공한다.
- 색은 보조 표현으로만 사용하고 선택명과 상태 텍스트를 함께 제공한다.
- 200% 텍스트 확대에서 항목명과 상세 이동 버튼이 겹치거나 잘리지 않아야 한다.
- 좁은 화면에서는 지도 위 고정 패널을 화면 높이를 넘는 독립 스크롤 영역 또는 하단 시트로 제공한다. 지도 조작 영역을 완전히 가리지 않아야 한다.
- WebGL/지도 로딩 실패 시에도 목록 기반 공정 → 공장 → 작업 위치 → 상세 이동을 제공한다.

### FR-7. 성능

- 대시보드 초기 번들에 조립 3D 뷰어와 공정별 상세 화면 코드를 포함하지 않는다.
- 작업 위치 데이터는 공장 선택 후 지연 조회하고, 같은 공장의 재선택은 합리적인 범위에서 캐시할 수 있다.
- 공정 또는 공장을 빠르게 바꿀 때 이전 비동기 응답이 최신 선택을 덮어쓰지 않아야 한다.
- 지도 강조는 베이스맵 전체를 재생성하지 않고 선택 레이어만 갱신해야 한다.

## 7. 데이터 및 상태 우선순위

| 상황 | 목록 | 지도 | 상세 이동 |
|---|---|---|---|
| 작업 위치·지도 키 모두 존재 | 표시 | 연결 지번 강조 | 허용 |
| 작업 위치 존재, 지도 키 없음 | 표시 + 위치 없음 안내 | 변화 없음 | 허용 |
| 지도 키가 지도 fixture에 없음 | 표시 + 매핑 불일치 안내 | 변화 없음 | 허용 |
| 작업 위치가 없음 | 빈 상태 | 공장 강조 유지 | 공장 현황만 허용 |
| provider 조회 오류 | 오류 + 재시도 | 공장 강조 유지 | 기존 공정/공장 링크 유지 |
| provider 미지원 | 준비 중 안내 | 기존 지도 동작 유지 | 기존 공정 화면 링크 유지 |

선택 상태의 우선순위는 `작업 위치 > 공장 > 공정 > 전체`이다. 작업 위치 선택 시 해당 지번을 가장 강하게, 같은 공장을 그다음, 같은 공정을 그다음으로 표현한다. 정확한 불투명도·색상 수치는 기존 디자인 토큰과 시각 회귀 검토에서 정하고 이 문서에서 새 수치를 발명하지 않는다.

## 8. 아키텍처 경계

- `DashboardPage`와 `shared/widgets/dashboard-map`은 `@/processes/**`를 import하지 않는다.
- 조립 변환 코드, 조립 명칭, 조립 상세 경로 생성은 `processes/assembly` 안에 둔다.
- 공정 모듈이 제공하는 값은 `ProcessModule.provides`와 `shared/model/processRegistry`를 통해 읽는다.
- 공정 모듈 간 직접 import를 금지한다.
- 새 공정 모듈을 만드는 작업이 아니므로 `app/bootstrap.ts`와 `app/i18next.d.ts`는 변경하지 않는다.
- 공통 계약 변경은 다른 공정 모듈에 provider 구현을 강제하지 않도록 선택적이어야 한다.
- `module.ts`는 경량을 유지하고 데이터 어댑터는 동적 import로 불러온다.

## 9. 단계별 구현 범위

### 1단계 — 정보 위계와 공통 계약

- 대시보드 제목/부제 카피 개선
- 공정 → 공장 → 작업 위치 선택 UI
- 선택적 `ProcessModule.provides` 계약과 레지스트리 조회 함수
- provider 미지원, 로딩, 빈 값, 오류, 지도 실패 대체 UI

### 2단계 — 조립 연결

- 지도 공장과 조립 공장 ID의 명시적 매핑
- 조립 `Location` → 공통 작업 위치 변환
- `yardLots` 기반 정반 위치 강조
- 기존 조립 정반현황 및 공장 현황 라우트 이동

### 후속 단계 — 다른 공정

가공·선행의장·선행도장의 실제 하위 위치 단위, 식별자, 화면 라우트가 권위 문서와 구현에서 확정된 뒤 각 모듈이 동일한 선택적 provider를 구현한다. 공정마다 단위가 다르면 `locationNounKey`로 실제 명칭을 표시한다.

## 10. 수용 기준

1. `/`에서 제목과 부제가 전체 현황, 4개 공정존 상태, 하위 현황 이동 목적을 사용자에게 전달한다.
2. 사용자가 지도 또는 패널에서 조립 공정과 조립 공장을 선택하면 그 공장의 베이(정반) 목록이 표시된다.
3. 조립 베이 항목에는 이름과 정반코드가 표시되며 선택적 값이 없을 때 가짜 호선·블록·상태가 생성되지 않는다.
4. 조립 베이의 `정반현황 열기`를 실행하면 정확한 기존 `/zones/assembly/:factoryId/:locationId`로 이동하고 브라우저 뒤로가기로 대시보드에 돌아온다.
5. 유효한 `yardLots`가 있는 베이를 선택하면 그 지번들이 강조되고, 없는 베이도 상세 화면으로 이동할 수 있다.
6. 공정을 바꾸면 이전 공장과 베이 선택이 제거되고, 공장을 바꾸면 이전 베이 선택이 제거된다.
7. 작업 위치 조회의 로딩, 빈 값, 오류, 재시도, provider 미지원 상태가 각각 구분되어 표시된다.
8. 지도 또는 WebGL이 실패해도 목록에서 조립 정반현황까지 이동할 수 있다.
9. 키보드만으로 조립 공정 → 공장 → 베이 선택 → 정반현황 이동 → 뒤로가기를 완료할 수 있다.
10. `npm run boundaries`가 통과하고 `shared/**`에 `@/processes/**` import가 추가되지 않는다.
11. 대시보드 초기 청크에 조립 3D 뷰어가 정적 import되지 않는다.
12. 빠른 공장 전환 테스트에서 늦게 도착한 이전 공장의 응답이 현재 베이 목록을 덮어쓰지 않는다.

## 11. 테스트 요구사항

### 단위 테스트

- 지도 공장 키 → 조립 공장 ID 매핑 성공/실패
- `Location`의 선택적 필드 및 `yardLots` 변환
- 공정/공장 변경 시 하위 선택 초기화
- 비동기 응답 경쟁 방지
- 작업 위치 지번 스포트라이트 우선순위

### 컴포넌트 테스트

- 로딩, 빈 값, 오류/재시도, provider 없음, 지도 키 없음
- 선택·재선택·상세 링크와 접근성 속성
- 긴 한글명, 코드 없음, 200% 텍스트 확대

### 통합/E2E 테스트

- 대시보드 → 조립 → 공장 → 베이 → 정반현황 → 뒤로가기
- 지도 공장 클릭과 패널 공장 클릭의 동일 결과
- 빠른 공장 전환과 실패 후 재시도
- 지도 로딩 실패 상태의 목록 기반 이동
- 모바일 폭과 데스크톱 폭의 패널 조작

### 시각·성능 테스트

- 2D/3D 각각에서 공정·공장·베이 강조 계층과 다크/라이트 앱 테마 확인
- reduced motion에서 즉시 카메라 이동 확인
- 기존 대시보드 초기 번들 크기와 변경 후 크기 비교
- 최대 예상 위치 수는 아직 미확정이므로, 운영 상한 확정 후 렌더링 시간 기준을 정한다.

## 12. 저장소에서 확인된 격차

1. 대시보드 문구는 상태 확인만 설명하고 공장·작업 위치 드릴다운을 안내하지 않는다.
2. 공정과 공장 선택은 있지만 공장 상세 카드가 지번 통계만 제공한다.
3. 조립 정반현황 라우트와 데이터는 존재하지만 공통 대시보드에서 안전하게 조회할 레지스트리 계약이 없다.
4. 지도 공장은 이름 중심이고 조립 공장은 별도 ID를 사용하므로 명시적 매핑이 필요하다.
5. `yardLots`는 연결 키로 구현돼 있으나 운영 `WORK_CNTR ↔ LOT` 마스터는 미확정이다.
6. 다른 세 공정의 작업 위치 단위와 상세 라우트는 현재 요청을 구현할 만큼 확정돼 있지 않다.
