# docs/design/uiux — 화면 설계 산출물 관리 규칙

이 폴더는 `uiux-designer` 서브 에이전트(및 사람 디자이너)가 만드는 **화면 설계 산출물**의 집이다. 와이어프레임·화면 정의표·상태 변형·흐름도·검수 리포트가 여기에 놓이고, 확정되면 기능 정의서로 옮겨 간다. 이 README가 폴더의 단일 진입점이며, 색인은 [화면목록.md](화면목록.md)에 있다.

---

## 1. 문서 계층 — 무엇이 정본인가

| 층 | 문서 | 역할 | 상태 전이 |
|---|---|---|---|
| 입력 | `.claude/agents/uiux-context/{prd,design-system,user-persona}.md` | 에이전트가 매 작업 읽는 요구·토큰·페르소나 | 버전이 오르면 산출물 메타의 "근거" 버전도 갱신 |
| 탐색·제안 | `docs/design/uiux/{시스템}/{PFX}-S##_{슬러그}.md` (+ `.svg`/`.drawio`) | **화면 설계서** — 와이어프레임·화면 정의표·상태 변형·미확정 | Draft → Review → Approved → Superseded |
| 확정 | `docs/spec/기능정의서_{시스템}.md` §4 화면 목록 · §6 화면별 상세 | 확정 화면의 정본. **화면 ID 채번 권한** | Approved 설계서를 반영하면 설계서는 Superseded(반영됨 vX.Y)로 동결 |
| 증빙 | `docs/assets/화면설계/{시스템}/{PFX}-S##_{슬러그}.png` | 구현 캡처·Figma export | 기능 정의서 §6이 참조 |

규칙:

- **화면 설계서는 채번 권한이 없다.** 신규 화면은 설계서에서 `OTD-S13(안)`처럼 `(안)`을 붙여 쓰고, 기능 정의서 §4에 반영될 때 확정 ID가 된다. (「인터페이스 정의서」가 IF-ID 채번 권한을 갖는 것과 같은 구조.)
- **미확정은 한 곳에서 번호를 관리한다.** 설계서마다 번호를 새로 만들지 않고 `uiux-context/prd.md` §10의 번호를 참조한다(`[미확정 3]`). 새 미확정은 prd.md §10에 추가를 제안한다.
- **Figma는 그리는 도구, 레포 Markdown이 정본.** 설계서 메타에 Figma 링크를 적고, 확정 시 PNG export를 `docs/assets/화면설계/`에 둔다. Figma에서만 존재하는 결정은 없는 것으로 본다.

## 2. 디렉토리 구조

```
docs/design/uiux/
├── README.md                          # 이 문서 — 규칙
├── 화면목록.md                         # 전 시스템 화면 ID 인벤토리 · 상태 · 링크
├── OT대시보드/
│   ├── OTD-S05_BAY현황판.md            # 화면 설계서 — 1화면 1파일
│   ├── OTD-S05_BAY현황판.svg           # 와이어프레임 벡터 (.svg 또는 .drawio, 비트맵 금지)
│   ├── 흐름도_위치축_객체축_합류.drawio   # 흐름도
│   └── 검수_OTD-S05_v0.1.md            # 페르소나 수용 기준 검수 리포트
├── 통합실적대시보드/                   # (향후) 착수 시 생성
└── Key-in실적/                        # (향후) 착수 시 생성
```

**현재 범위 — OT 대시보드만.** 지금 설계 대상은 `OT대시보드/`뿐이다. 통합실적대시보드(IPD)·Key-in 실적(KEY)은 향후 착수 시 같은 규칙으로 폴더를 만든다. 그 전까지 두 폴더는 두지 않는다.

- 시스템 슬러그는 `docs/assets/화면설계/`와 같은 값을 쓴다: `OT대시보드` · `통합실적대시보드` · `Key-in실적`.
- **1화면 1파일.** 병렬 작업·리뷰·상태 전이가 화면 단위로 끊기도록 한다.
- 파일명에 버전을 넣지 않는다(이력은 git). 검수 리포트만 검수 시점 버전을 붙인다.
- 와이어프레임 벡터는 설계서 옆에, PNG export는 `docs/assets/화면설계/{시스템}/`에.
- 초안·스케치·Figma 원본 export 같은 중간물은 `.work/`(gitignore)에 둔다.

## 3. 화면 설계서 규격 (house-style 준수)

```markdown
# 내업 공정실적 자동수집 시스템
# OTD-S05 BAY/셀 현황판 화면 설계서

**버전:** v0.1
**상태:** Draft            <!-- Draft | Review | Approved | Superseded(반영됨 기능정의서 vX.Y) -->
**작성:** uiux-designer (검토: 이태훈 PM)
**근거:** prd v0.1 · design-system v0.1 · user-persona v0.1 · 기능정의서_OT대시보드 v0.1
**Figma:** (링크, 있으면)

---

## 1. 목적 · 페르소나 질문        <!-- P1/P2/P3의 어떤 질문에 답하는가 한 줄 -->
## 2. 진입 · URL · 화면 ID(안)     <!-- 현 구현 ID를 잇는다. 신규는 "(안)" -->
## 3. 와이어프레임                 <!-- 1440×900 중충실도. SVG/drawio 링크 + 번호 마커 ①②… -->
## 4. 화면 정의표
| 번호 | 요소 | 내용 / 규칙 | 데이터 출처 (실시간 / 레거시 일 1회) | 상태 / 미확정 |
## 5. 상태 변형                    <!-- 로딩 · 빈 · 오류 · 못 찾음(사외/미착수/범위 외) · 수집 이상 -->
## 6. 미확정                       <!-- [미확정 n] — prd.md §10 번호 참조 -->
## 변경 이력
| 버전 | 날짜 | 내용 |
```

- 레거시 유래 값에는 "레거시 기준 MM-DD HH:mm", 센서 유래 값에는 "실시간" 라벨을 정의표에 적는다.
- 구현 용어(State Machine·NATS·Hot Data DB)는 쓰지 않는다. 화면 레이블은 권역 › 공정 단계 › 공정 상태.
- 색·폰트·컴포넌트는 design-system.md 토큰 이름으로만 적는다. 없는 것은 `[확인 필요]`.

## 4. 운영 규칙

| 항목 | 규칙 |
|---|---|
| 브랜치 | `feature/uiux-{화면ID}` 또는 현재 `*/design-uiux` 브랜치 |
| 커밋 | `docs(uiux) : OTD-S05 BAY 현황판 설계서 v0.1` |
| 리뷰 단위 | 화면 1개 = PR(또는 커밋) 1개. 검수 리포트를 같은 PR에 포함 |
| 상태 전이 | Draft(작성 중) → Review(검토 요청) → Approved(확정, 기능 정의서 반영 대기) → Superseded(반영됨) |
| 기능 정의서 반영 | Approved 되면 `functional-spec` 스킬로 §4·§6 갱신 → 설계서 상태를 Superseded로, `화면목록.md` 링크 갱신 |
| 캡처 | 구현 후 캡처는 `docs/assets/화면설계/{시스템}/{PFX}-S##_{슬러그}.png` |
