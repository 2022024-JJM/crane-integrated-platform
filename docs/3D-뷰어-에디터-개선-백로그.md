# 3D 뷰어·에디터 개선 백로그

> 2026-08-13 3방향 전수 감사(뷰어 런타임 / 에디터 / 성능 안티패턴) 결과.
> 목적: **유니티 없이 WebGL(Three.js)로 관제 모니터링·디지털 트윈이 충분하다**는 것을 어필하기 위한 성능·비주얼·신뢰성 개선 목록.
>
> 종합 평가 — 코드 기본기는 이미 상급이다. useFrame 내 setState 0건(전부 ref mutate), zustand `getState()` 폴링, lazy material clone, BVH 레이캐스트 가속, 4Hz HUD 스냅샷이 주석과 함께 일관 적용되어 있다. **병목은 코드가 아니라 에셋(압축 전무·4K PNG), 로딩 UX, 에디터-뷰어 이중 구현 드리프트에 몰려 있다.**

## P1 — 성능 (어필 포인트 ①: "웹인데 빠르다")

### 1-1. GLB 에셋 파이프라인 ★ 남은 것 중 효과 최대

압축 확장(draco/meshopt/KTX2) 사용 **0건**. 실측:

| 파일 | 크기 | 문제 |
|---|---|---|
| `goliath_crane.glb` | 13.1MB | 용량의 70%가 **4096×4096 PNG 1장** (GPU 상주 ~89MB) |
| `LLC_002.glb` | 10.4MB | 4K PNG 1장, 씬에 ×2 인스턴스 |
| `TTC-28.glb` | 9.6MB | 17만 삼각형 비압축 float32 (텍스처 없음) |
| `crane.glb` | 6.8MB | **드로우콜 91개** — 머티리얼 7개뿐이라 병합 시 91→7 |
| region 진입 총합 | 25~36MB | dock-1 기준 36MB 다운로드 |

- 조치: `gltf-transform optimize` 일괄 (meshopt + KTX2 + 4K→2K 리사이즈) + `useGLTF`에 MeshoptDecoder/KTX2Loader 연결
- 기대: **다운로드 36MB → 6~8MB, VRAM 1/5**
- 보조: `TTC-27`(7.5MB)과 `TTC-K5000`(2.6MB)은 삼각형 수가 완전히 동일(110,124) — 중복 정리 후보. 씬에서 참조 안 되는 대형 GLB(car/human/goliath_body/trolley 등 ~40MB)의 배포 포함 여부 점검

### 1-2. 로딩 잔여 — 프리로드

- 오버레이는 적용됨. 남은 것: 모니터링 경로 `useGLTF.preload` 0건 — 씬 JSON이 필요한 GLB 목록을 이미 알고 있으므로 라우트 진입 전(지역 카드 hover, 대시보드 로드 직후) 프리로드하면 체감 지연 대부분 은닉 가능
- `apps/shell/index.html`에 preconnect/modulepreload 힌트 0개

### 1-3. frameloop demand

- `scene-objects-edit-canvas`(useFrame 0개)와 `goliath-3d-viewer`는 정지 씬인데 60fps 풀 렌더 → 발열/배터리 낭비
- mro2 썸네일(`crane-thumb-scene.tsx`)의 `frameloop="demand"` + `invalidate()` 패턴이 정확한 참조 구현 — 그대로 복제
- 모니터링/리플레이 뷰는 러너(useFrame) 기반이라 always 유지가 타당

### 1-4. LiDAR 스트림 버퍼 재사용 (골리앗)

- `cabin-monitoring-view.tsx` — WS 메시지(10Hz)마다 `setState` + **새 Float32Array + 새 BufferGeometry** → 페이지 전체 리렌더 + GPU 재업로드
- `point-cloud-viewer.tsx` — 프레임당 720KB 버퍼 신규 할당(60K 포인트 × 색상)
- 조치: 이미 구현돼 있는 `point-cloud-stream-store` 패턴(고정 크기 버퍼 1회 할당 + `array.set()` + `needsUpdate` + `drawRange`)으로 통일
- 기대: 골리앗 LiDAR 화면 프레임 드랍·GC 압박 제거

### 1-5. region 전환 메모리 정리

- `useGLTF.clear()` 호출처 **0건** — region 순회 시 CPU 캐시 ~93MB + VRAM ~270MB 단조 증가, 장시간 관제 세션에서 탭 크래시 위험
- BVH(`boundsTree`)도 해제 경로 없음 (`disposeBoundsTree` 등록만 되고 호출 0건)
- 조치: region 이탈 시 미사용 URL만 clear + boundsTree 해제 훅

### 1-6. WebGL 컨텍스트 다중 마운트

- mro2 자산 그리드: 카드마다 `<Canvas>` 1개 → 자산 수만큼 컨텍스트, 한도(8~16) 초과 시 오래된 컨텍스트 강제 손실(회색 썸네일)
- 조치: 이미 있는 `offscreen-preview-renderer`(공유 렌더러 + blob 캐시)로 이미지화
- 골리앗 vision 페이지도 타일마다 Canvas — 컨텍스트 수 모니터링 필요
