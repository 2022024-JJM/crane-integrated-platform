# 3D 편집·모니터링 단위 테스트 도입 계획

작성일: 2026-09-01

`packages/` 의 3D 코드에 vitest 단위 테스트를 도입하는 작업 지시서다.
**이 문서를 그대로 구현 에이전트에 전달해도 되도록** 배경·범위·금지사항·완료 기준을
한 곳에 담았다.

관련 코드
- 편집 화면 로직: `packages/widgets/src/scene-editor/model/`
- 편집 캔버스: `packages/widgets/src/3d/`
- 모니터링 화면: `packages/features/src/3d/`
- 3D 도메인 헬퍼: `packages/domain/src/3d/lib/`
- 기존 테스트 선례: `apps/philly-shipyard/src/pages/asset-management/lib/compute-frontal-view.test.ts`

---

## 목적

렌더링 결과(픽셀)가 아니라 **순수 로직과 상태 전이**를 대상으로 회귀를 막는다.
3D는 "눈으로 봐야 아는" 영역이 넓지만, 실제 버그의 상당수는 좌표 계산·씬 JSON
파싱·undo 스택·리플레이 상태 전이처럼 **화면 없이 검증 가능한 곳**에서 난다.
이 계층부터 덮는다.

## 현재 상태 (재조사 불필요)

- `packages/{core,domain,features,ui,widgets}` 는 vitest 의존성도 `test` 스크립트도 **없다**.
  전부 새로 세팅해야 한다.
- 테스트가 존재하는 곳은 `apps/{philly-shipyard,mro2,indoorshop}` 뿐이고,
  **3D 관련 테스트는 0개**다.
- `turbo.json` 에 `test` task 는 이미 정의돼 있다. 패키지에 `test` 스크립트만 추가하면
  `pnpm test` 에 물린다.
- 설정 선례: `apps/philly-shipyard/vitest.config.ts`
  (`environment: 'node'`, `include: ['src/**/*.test.ts']`, `setupFiles` 로 TZ 고정)

### 테스트 파일 배치 (필수)

테스트는 대상 코드 옆에 나란히 두지 않고 **`__tests__/` 디렉토리로 분리**한다
(`AGENTS.md` 의 "테스트 파일 배치 규약" 참조).

```
packages/features/src/3d/lib/
├── __tests__/
│   └── scene-shadow.test.ts
└── scene-shadow.ts
```

- `__tests__/` 는 대상과 **같은 세그먼트**(`lib/`, `model/`) 안에 둔다
- 파일명은 `{대상}.test.ts` 로 1:1 대응
- fixture·헬퍼도 `__tests__/` 안에 둔다. `lib/`·`model/` 에 테스트 전용 파일을 만들지 않는다
- `__tests__/` 의 파일은 슬라이스 `index.ts` 에서 export 하지 않는다
- `apps/mro2` 에 나란히 둔 기존 파일이 남아 있으나 이번 작업 범위가 아니다

## 작업 1 — vitest 인프라

`packages/domain`, `packages/features`, `packages/widgets` 에 각각:

- `vitest` devDependency 와 `"test": "vitest run"` 스크립트.
  버전은 `apps/philly-shipyard` 가 쓰는 vitest 버전과 **동일하게** 맞춘다 —
  워크스페이스에 버전이 갈라지지 않게
- `vitest.config.ts` — 기본 `environment: 'node'`.
  훅/스토어 테스트가 필요한 파일에만 `// @vitest-environment jsdom` 을 붙인다.
  **jsdom 을 전역 환경으로 설정하지 말 것** — 순수 로직 테스트까지 느려지고,
  DOM이 없어야 드러나는 의존성이 숨는다.
- 워크스페이스 alias(`@crane/*`)가 테스트에서 해석되도록 설정

## 작업 2 — 순수 로직 테스트

각 파일의 실제 구현을 먼저 읽고, **현재 동작을 고정하는 특성화 테스트**로 시작한다.
구현을 바꾸지 않는다.

### 편집 화면 — `packages/widgets/src/scene-editor/model/`

| 파일 | 검증할 것 |
|---|---|
| `use-scene-history.ts` | undo/redo 스택 경계, 최대 깊이, 분기 후 redo 무효화 |
| `scene-snapshot.ts` | 스냅샷 동등성 판정, 변경 감지 오탐/누락 |
| `scene-manipulation-actions.ts` | 추가·삭제·복제·변환 액션의 상태 전이 |
| `use-scene-persistence.ts` + `domain/3d/lib/scene-dev-storage.ts` | 저장·로드 왕복, 배포 해시가 더 새로우면 로컬 저장본을 폐기하는 규칙 |

### 3D 도메인 — `packages/domain/src/3d/lib/`

| 파일 | 검증할 것 |
|---|---|
| `sanitize-scene-info.ts` | 잘못된/누락 필드 방어, 구버전 씬 JSON 마이그레이션 — **회귀 위험 1순위** |
| `sea-submersion.ts` | 해수면 높이별 잠김 계산 |
| `math-utils.ts`, `mesh-path.ts`, `model-path-utils.ts` | 좌표·경로 변환 |
| `map-surface-raycast.ts` | three 객체를 직접 만들어 히트 좌표 검증 |
| `model-bottom-offset-cache.ts` | 캐시 히트/무효화 |

### 모니터링 화면 — `packages/features/src/3d/`

| 파일 | 검증할 것 |
|---|---|
| `lib/scene-shadow.ts` | `isSceneShadowEnabled` / `sceneCanvasShadows` 진리표 |
| `model/use-replay-player-store.ts` + `use-replay-player-runner.ts` | seek/play/pause/속도 변경. `vi.useFakeTimers()` 로 결정론적으로 |
| `model/use-collision-guard-simulation.ts` | 좌표 주입 → 경보 상태 전이 경계값 |
| `model/use-value-mapper-store.ts` | 등록·리셋·원점 복귀 |
| `model/use-scene-views-store.ts` | 북마크 저장·복원 |

### 프리뷰 — `packages/widgets/src/3d/lib/`

| 파일 | 검증할 것 |
|---|---|
| `preview-camera-framing.ts` | 모델 크기별 프레이밍 |
| `preview-render-queue.ts` | 큐 키 중복 제거, abort, 컨텍스트 로스트 시 대기자 reject. 비동기+타이머가 얽히므로 `vi.useFakeTimers()` 로 결정론적으로 — 실타이머로 flaky 테스트를 만들지 말 것 |

`three` 객체를 직접 생성해 검증하는 패턴은
`apps/philly-shipyard/src/pages/asset-management/lib/compute-frontal-view.test.ts` 를 따른다.

## 작업 3 — 테스트 가능성 개선 (발견 시에만, 최소 범위)

`ui/*.tsx` 안에 인라인된 수치 계산이 있으면 같은 슬라이스의 `lib/` 로 순수 함수를
추출하고 테스트를 붙인다. `packages/features/src/3d/lib/scene-shadow.ts` 의 주석이
이 원칙의 선례다. **동작 변경은 금지, 순수 이동만.**
