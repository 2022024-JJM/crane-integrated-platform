# 3D 자산 라이브러리 — 자산의 단일 원천, 목록·미리보기·상세 뷰어·버전 비교·상태·배치 속성·사용처, 편집 팔레트와 씬의 자산 참조, 서버 없는 저장

> 이 문서는 현재 상태만 적는다. 갱신은 덧붙이기가 아니라 덮어쓰기. 날짜·경위·사라진 UI 는 쓰지 않는다.

조선소(옥포·필리)에서 쓰는 3D 모델·지도·배경·도면·CAD 원본을 한곳에서 찾고 버전과 상태를 관리하는 전사 공용 화면이다. region 하위가 아닌 최상위 경로(`/asset-library`, `/asset-library/:assetId`)에 있고 사이드바 "자산" 그룹에서 들어간다. GLB 를 만들고 압축하는 파이프라인은 `docs/agents/assets-glb.md`.

**모델·지도·배경의 원천은 이 라이브러리 하나다.** 3D 화면 편집의 팔레트(모델·맵·배경 탭)가 여기서 목록을 만들고, 씬은 놓은 자산을 id 와 버전으로 가리킨다. 코드에는 자산 목록이 없다.

## 동작

### 자산의 원천

자산은 전부 `library.json` 의 레코드다. 문서에 있는 것이 라이브러리의 전부이고 코드가 채워 넣는 자산은 없다 — 자산을 더하려면 등록하고, 빼려면 지운다.

- 라이브러리 디렉터리가 생기기 전부터 배포돼 있던 파일은 옛 경로(`/models/*.glb`·`/maps/*.glb`·`/scenes/*.exr`·`/drawings/**`)에 그대로 있고 그 자산의 버전 1 이다. 새 버전은 항상 라이브러리 디렉터리(`files/<id>/v<N>/`)로 들어간다.
- 없어진 자산을 가리키는 연결(`relatedAssetIds`)과 컬렉션 항목은 문서를 읽을 때 걷어낸다.

### 종류

`model`·`map` 은 씬에 놓는 3D 자산(GLB)이다(`isGeometryAssetKind`) — 기하 통계·권장 상한은 이 둘에만 있다. `environment` 는 씬의 배경(등장방형 파노라마 EXR)이다. 씬에 놓는 것이 아니라 씬이 하나를 고르는 것이라 "미사용" 을 판정하지 않는다. 이 셋이 3D 화면 편집에서 쓰는 종류다(`isSceneAssetKind`) — 팔레트에 나오고 배치 속성을 가진다. `drawing`(화면에서 보는 도면: PDF·SVG·그림)과 `cad`(CAD 원본: `ASSET_CAD_EXTENSIONS`)는 문서형 자산이고(`isDocumentAssetKind`) 도면 번호·리비전을 가진다. 종류는 파일 확장자가 정한다(`getAllowedAssetKinds`) — GLB 만 모델·지도 중에서 고른다. CAD 원본은 미리보기 없이 보관·버전 관리만 한다.

배경은 등록할 때 EXR 헤더에서 해상도를 읽는다. 한 변이 `ASSET_ENVIRONMENT_MAX_SIZE` 를 넘으면 받지 않는다 — 그런 텍스처는 GPU 상한에 걸려 배경이 검게 나오고, 파일 이름이나 크기로는 해상도를 알 수 없다.

### 배치 속성

3D 화면 편집에서 자산을 씬에 놓을 때의 기본값이다(`AssetRecord.placement`). 상세의 "배치 속성" 탭에서 고친다.

- 편집 팔레트에 표시(모델·지도·배경) — 끄면 팔레트에 나오지 않는다. 화면 코드가 직접 로드하는 부품처럼 씬에 놓을 일이 없는 자산용이다.
- 지도의 역할(바닥·주변 지형)과 기본 위치, 모델의 수면에 놓기.
- 값은 **놓는 순간 씬에 복사**된다. 그 뒤로는 씬이 자기 값을 가지므로 여기서 바꿔도 이미 놓인 것은 달라지지 않는다.
- 기본 동작인 값(역할 바닥·원점·꺼진 스위치)은 저장하지 않는다. 종류에 맞지 않는 항목은 떨어지고, 남는 것이 없으면 필드가 없다.
- 기본 스케일은 없다. 자산은 실척(m)으로 들어오고 씬에는 등배로 놓인다.

### 탐색 계층

자산이 "어디에 있는가" 는 종류(모델·지도·배경·도면·CAD)다. 그 아래의 세부 분류는 전부 카테고리가 맡는다 — 실내·실외, 크레인·블록, 옥포·필리 같은 구분을 따로 된 속성으로 두지 않는다. 계층은 저장된 구조가 아니라 자산의 속성(`kind`·`categories`)에서 그때그때 만든다.

- 종류 줄은 자산이 없어도 전부 나온다(그 자리에 무엇을 둘 수 있는지 보인다). 누르면 그 종류 전부를 보고 고른 카테고리는 풀린다.
- 종류 아래에 그 종류의 자산이 가진 카테고리가 체크박스로 놓인다. 펼친 종류 아래에만 나오고, 순서는 그 종류에서 많이 쓰인 순으로 고정이다 — 체크해도 줄이 자리를 바꾸지 않는다. 대소문자만 다른 카테고리는 한 줄이다.
- 여러 개를 체크하면 **모두 가진** 자산만 남는다(`queryAssets` 와 같은 규칙). 그래서 체크 안 한 카테고리의 수는 "지금 고른 것에 이 카테고리까지 걸면 남는 수" 이고, 0 이면 고를 수 없다.
- 줄의 수는 그 줄을 누른 탐색 결과의 수와 같다(테스트가 고정한다).
- 다른 종류의 카테고리를 체크하면 그 종류로 옮겨 가며 그 카테고리 하나로 새로 시작한다. 전체를 보는 중이면 고른 카테고리를 들고 그 종류로 들어간다(`toggleAssetScopeCategory`).
- 계층 위의 위치(`AssetScope`)는 종류까지다. 화면 머리말이 그 길을 적는다. 체크한 카테고리는 검색·상태와 같은 **필터**라 결과 위에 칩으로 나오고 "필터 초기화" 에 풀린다 — 위치는 남는다.
- 등록할 때 보고 있던 종류와 같은 종류의 파일이면 거기서 체크해 둔 카테고리로 시작한다. 카테고리를 붙이는 자리(등록·정보 탭)는 같은 종류에서 이미 쓰는 카테고리를 권한다(`listAssetKindCategories`) — 철자가 갈리면 체크박스가 둘로 나뉜다. 권하는 목록은 입력란에 치는 글자로 거르고(`listCategorySuggestions`), 네 줄을 넘으면 그 안에서 스크롤한다.

### 버전·상태

- 버전 파일은 불변이고 경로에 자산 id 와 버전 번호가 들어간다. dev 미들웨어는 이미 있는 버전 경로에 쓰지 않는다.
- 버전은 추가가 기본이다. 지울 수 있는 것은 **게시된 적 없는 버전(초안·반려)** 뿐이고(`canRemoveAssetVersion`), 현재 버전과 마지막 남은 버전은 지울 수 없다. 지운 번호는 다시 쓰지 않는다 — 다음 번호는 이력까지 보고 정한다.
- 메타데이터 수정은 버전을 만들지 않는다. 파일을 바꾸면 새 버전(초안)이 되고 현재 버전 포인터는 그대로다 — 사용자가 "현재 버전으로 지정" 으로 옮긴다. 롤백도 포인터 이동이다.
- 상태는 **버전 단위**이고 전이는 `asset-versions.ts` 의 표만 따른다. 철회·반려된 버전은 현재가 될 수 없다.
- **씬이나 화면 코드가 쓰고 있는 버전은 철회할 수 없고, 한 버전이라도 쓰이는 자산은 지울 수 없다.** 스토어가 그 순간 사용처를 다시 읽어 확인한다 — 화면을 연 뒤에 씬에 놓인 것도 막는다. 읽지 못한 씬이 있으면 "안 쓰인다" 를 믿지 않고 막는다(씬에 쓰지 않는 종류는 예외).
- 문서형 자산(도면·CAD)은 버전 번호와 별개로 리비전 표기(`revision`)와 도면 번호(`drawingNo`)를 가진다.
- 변경 함수는 바뀐 것이 없으면 입력 참조를 그대로 돌려주고, 스토어는 그때 저장하지 않는다.
- 이력은 자산마다 상한까지 남는다. 같은 사람이 짧은 시간 안에 이어 고친 메타데이터는 한 줄로 묶는다. 자동 생성 썸네일은 이력에 남기지 않는다.

### 처리할 일

목록의 대부분은 손 갈 데 없는 자산이다. 손이 가야 하는 이유(검토 대기·반려·검토 요청 전·새 버전 있음·권장 상한 초과·미사용)를 `getAssetAttention` 한 곳에서 판정하고, 레일의 "처리할 일" 개수·카드의 표식·미리보기와 상세의 안내·`attn` 필터가 전부 이 판정을 쓴다.

- "미사용" 은 사용처를 읽은 뒤에만 판정한다. 도면·CAD·배경은 놓인 곳이 없어도 미사용이 아니다. 화면 코드가 직접 로드하는 모델은 그 사용이 사용처에 세어져 있어 미사용으로 잡히지 않는다 — 카테고리로 묻지 않는다.
- 카드에는 가장 급한 이유 하나만 붙고, 문제없는 자산에는 아무것도 붙지 않는다.
- 안내 줄을 누르면 그 일을 처리하는 버전·탭으로 간다(`resolveAttentionTarget`). 이미 그 자리에 와 있으면 안내하지 않는다.
- "새 버전 있음" 은 검토를 통과한(승인·게시) 새 버전이 아직 현재로 지정되지 않았을 때만이다. 검토 전·검토 중인 새 버전은 그 상태의 이유가 따로 알린다 — 같은 버전에 이유가 둘 붙지 않는다.
- 미리보기는 현재 버전이 아니라 **지금 손이 가야 하는 버전**을 보여 준다(`pickPreviewVersion` — 걸린 필터의 대상 버전 → 검토 중인 버전 → 현재 버전). 한 자산을 보는 동안에는 버전을 바꿔치지 않아, 승인 → 게시 → 현재 버전으로 지정을 패널에서 이어서 할 수 있다.

### 수명주기

상태는 드롭다운 속에 두지 않고 길(초안 → 검토 중 → 승인됨 → 게시됨)로 펼쳐 지금 위치와 다음 걸음을 함께 보인다(`asset-lifecycle.tsx`). 반려·철회는 길 위의 한 지점에 멈춰 선 상태로 그린다. 앞으로 가는 걸음은 넓은 주 버튼, 되돌리는 걸음(반려·철회)은 작은 보조 버튼이다. 게시된 버전은 길을 다시 늘어놓지 않고 한 줄로 적으며, 되돌리는 걸음(철회)은 머리 줄에 작게 둔다. 미리보기 패널과 상세 인스펙터 맨 위(어느 탭에서도 보인다)에 있다.

### 저장 — 서버 없이

화면은 `AssetLibraryRepository` 만 안다. 스토어는 바꿀 때마다 자동 저장하고(저장 버튼 없음), 저장을 한 줄로 세워 실행 시점의 최신 상태를 쓴다. 실패하면 메모리 상태를 유지하고 재시도를 권한다.

저장은 문서를 통째로 쓴다. 그래서 다음 네 가지를 지킨다.

- **다 읽은 뒤에만 고치고 쓴다.** 읽는 중·읽기 실패 상태의 메모리는 빈 목록이라, 그때 쓰면 문서가 빈 것으로 덮인다. 스토어의 모든 변경이 `status === 'ready'` 를 먼저 본다.
- **읽은 뒤로 다른 곳에서 바뀌었으면 쓰지 않는다.** dev 는 읽은 글자의 지문(`hashAssetLibraryText`)을 헤더로 보내 미들웨어가 지금 파일과 견주고, 브라우저 저장소는 봉투의 `revision` 을 견준다. 다르면 `AssetLibraryConflictError` → `saveState: 'conflict'`. 다시 읽어야(`load({ force: true })`) 풀리고, 그 전까지는 쓰지 않는다. 다시 읽으면 저장 못 한 변경은 버려진다.
- **읽지 못한 것을 지우지 않는다.** 모양이 틀리거나 이 앱보다 새 스키마의 문서는 빈 문서로 열지 않고 읽기 실패로 알린다. 방어를 통과하지 못한 개별 레코드는 저장소가 원본 그대로 들고 있다가 저장할 때 도로 붙인다.
- **문서 저장이 성공한 뒤에만 파일을 지운다.** 자산·버전 삭제는 저장에 실패하면 화면을 지우기 전으로 되돌리고 파일을 건드리지 않는다.

여러 자산을 한 번에 고치는 일(일괄 작업)은 한 번만 저장한다(`updateManyMetadata`·`transitionManyStatus`·`removeManyAssets`).

- **dev** — 문서는 `POST /__dev/asset-library` 로 `public/asset-library/library.json` 에, 파일은 `/file?key=` 로 `files/<id>/v<N>/<name>`·`thumbnails/<id>.png` 에 쓴다. 커밋하면 배포의 기준값이 된다.
- **운영** — 미들웨어가 없어 **파일을 올리고 지울 수 없다**(`canManageFiles`): 자산 등록·새 버전 올리기·자산과 버전 삭제는 dev 에서 하고 배포한다. 이름·카테고리·상태·배치 속성 같은 문서 수정은 되고 localStorage 봉투에 남는다 — **그 브라우저에만 남는다**(화면이 그렇게 알린다). IndexedDB 에는 그 브라우저가 찍은 썸네일만 들어간다. 봉투의 `baseVersion` 이 현재 배포 문서의 해시와 다르면 배포본이 이긴다(씬·가상 카테고리와 같은 규칙).
- 문서에는 스키마 버전이 있다(`ASSET_LIBRARY_SCHEMA_VERSION`). 자기보다 새 문서는 읽기를 거부하고(읽은 척 모르는 필드를 떨군 채 저장하지 않는다), 옛 문서는 읽을 때 지금 모양으로 올린다 — 카테고리를 `tags` 로 적던 판이 그렇다(`sanitize-asset-library.ts`).
- 자산을 지우면 라이브러리 디렉터리의 파일과 함께 옛 배포 경로의 버전 파일도 지운다. 미들웨어는 정해진 디렉터리·확장자만 받는다(`isRemovableLegacyAssetPath`) — 같은 디렉터리의 씬 JSON 을 지우는 길이 되지 않는다.
- 브라우저 저장소의 키는 배포 파일과 같은 상대 경로다. 서버가 생기면 같은 인터페이스의 구현을 하나 더 만들어 `getAssetLibraryRepository` 의 분기만 바꾼다.

### 등록 시 최적화

모델·지도(GLB)를 등록하거나 새 버전을 올릴 때 최적화해 저장할 수 있다(기본 켜짐). 종류마다 다른 파이프라인을 탄다 — 모델은 `scripts/optimize-glb.mjs`, 지도는 `scripts/optimize-map.mjs`. dev 미들웨어가 그 스크립트를 `--single <입력> <출력> --report <json>` 로 자식 프로세스에서 돌린다(`optimizeGlbBuffer`). 순서·정책은 `docs/agents/assets-glb.md`.

- **고를 것은 켜고 끄는 것 하나다.** 지도의 타일·LOD·양면 유지·압축 여부는 파이프라인이 파일을 재서 정하고, 무엇을 골랐는지를 보고(`report`)로 돌려준다. 화면은 그 줄들을 등록 알림에 붙인다(`fileReport` → `summarizeFileReport`).
- dev 서버에서만 된다(`AssetLibraryRepository.canOptimize`).
- 저장되는 것은 최적화한 파일이고, 올린 원본은 `assets-src/asset-library/<id>/v<N>/<name>` 에 둔다(`ASSET_LIBRARY_ORIGINALS_DIR`). 자산·버전을 지우면 원본도 지운다. 100MB 를 넘는 원본은 미들웨어가 `.gitignore` 에 올린다 — 따로 보관한다.
- 지도 파이프라인이 루트 오프셋을 지웠으면 그 값이 **새로 등록하는** 지도의 기본 위치가 된다(Blender 씬에 놓여 있던 자리). 새 버전에는 적용하지 않는다.
- 버전의 `sizeBytes` 는 저장된 파일의 크기, `originalSizeBytes` 는 올린 원본의 크기다(있으면 최적화한 버전). `contentHash` 는 **원본**의 해시다 — 같은 원본을 다시 올리는 것을 알아보는 값이라.
- 최적화가 실패하거나 결과가 원본보다 작지 않으면 원본 그대로 저장한다. 등록을 막지 않고, 화면이 이유와 함께 알린다.

### 통계

- 배포 파일의 크기·삼각형 수 등은 `pnpm assets:stats` 가 `stats.json` 에 미리 뽑아 둔다. 목록은 이 표로 표시·정렬하므로 GLB 를 열지 않는다. GLB 가 아닌 파일(배경 EXR·도면)은 크기와 해시만 적는다.
- 표의 항목은 **지금 배포된 파일과 해시가 같을 때만** 쓴다(자산 해시 매니페스트와 비교) — 낡은 항목은 비운다. `pnpm assets:stats --check` 가 낡은 항목을 보고한다.
- 이 화면에서 올린 파일은 뷰어가 처음 열 때 재서 버전 레코드에 채운다.
- 스크립트와 브라우저 측정은 같은 기준이다: LOD 사본(`lod > 0`)은 렌더 기준에서 빼고, 메쉬는 프리미티브 단위로 센다. 노드 수만 기준이 다르다(glTF 노드 vs three 객체) — 그래서 상세 화면은 저장된 값이 있으면 그것을 쓴다.
- 권장 상한(`ASSET_BUDGET`)은 `scripts/scene-perf-report.mjs` 의 모델 단위 경고 기준과 같은 값이다. 초과해도 등록을 막지 않는다.

### 뷰어

- 모니터링 씬 뷰어(`ThreeSceneViewer`)를 쓰지 않는다 — 그쪽은 지도 위를 나는 카메라고 여기는 물체 하나를 돌려 보는 카메라다. 캔버스는 `frameloop="demand"` 이고 자동 회전을 켠 동안만 계속 그린다.
- 조명은 방향광 + 절차적 반사 환경(three `RoomEnvironment`)이다. 금속·도장면은 비칠 것이 있어야 재질로 읽히고, 폐쇄망이라 HDRI 프리셋을 받을 수 없다.
- 바닥 격자는 멀어질수록 흐려지는 무한 격자(drei `Grid`)다. 칸 크기는 물체 크기에서 고른다(`pickGridStep`).
- 뷰어 위 조작은 배경·테마와 무관한 어두운 유리판 위에 놓고, 켜진 상태는 흰 판으로 나타낸다. 브랜드 주황은 탭 밑줄·선택 표시에만 쓴다.
- 치수는 정점 단위로 잰 경계 상자다. 씬 단위가 m 가 아닌 씬(`dock-in`)에 놓는 자산은 실제 길이와 다르다.
- 치수선·라벨은 배경과 대비되는 무채색이다. 조선소 크레인은 주황·노랑 도장이 많아 브랜드 주황은 물체와 섞인다.
- 뷰 모드는 메쉬의 material 슬롯만 바꿨다가 되돌린다(원본 머티리얼은 캐시와 공유).
- LOD 단계 미리보기는 최상위 캐리어만 켜고 끈다(`docs/agents/assets-glb.md` 와 같은 계약).
- 배경은 따로 둔 파노라마 뷰어(`asset-environment-viewer.tsx`)로 본다. 씬과 같은 방식으로 EXR 을 `scene.background` 에 걸고 렌더러의 톤매핑을 거치며, 카메라는 제자리에서 돌기만 한다(끌면 그림이 손을 따라온다). 시작 시점은 파노라마의 한가운데(+X)다. 화면을 떠나면 그 파일의 로더 캐시를 놓는다.
- 배경의 썸네일은 처음 보이는 시점의 가운데를 가로로 긴 비율로 자른 불투명 그림이고(`centerCropRect`), 목록에서는 받침 위에 띄우지 않고 자리를 채운다.
- 썸네일은 투명 배경 PNG 이고, 물체가 차지한 영역만 잘라 정사각에 채운다(`lib/thumbnail-crop.ts`) — 가는 물체도 목록에서 같은 크기로 보인다. 원천 순서는 저장된 썸네일 → 그림 도면은 파일 자체 → 종류 아이콘. 썸네일이 없는 자산은 처음 열렸을 때 한 번 자동으로 찍는다. 편집 팔레트와 대시보드도 이 썸네일을 쓴다(`getAssetThumbnailPath`).
- 뷰어 아래 표제란은 지금 올라온 파일(파일명·버전·크기·치수·삼각형)만 적는다. 이름과 상태는 머리말과 진행 단계가 말한다.
- 화면을 떠나면 그 파일의 GLTF 캐시를 놓는다.
- 표시 상태(뷰 모드·배경·격자·치수·자동 회전)는 뷰어가 직접 들거나 바깥이 넘긴다(`display`). 조작 도구는 `toolbar` 로 전부·좁은 자리용·없음을 고른다.
- 캔버스는 이벤트를 걸 요소를 직접 받는다(`eventSource`). R3F 는 만들어진 뒤 비동기로 이벤트를 거는데, 그 사이 뷰어가 사라지면 없는 요소에 걸다 던진다.

### 버전 비교

상세에서 보고 있는 버전과 다른 버전 하나를 나란히 놓는다(`?compare=`). 어느 쪽을 보고 있었든 왼쪽이 옛 버전, 오른쪽이 새 버전이고 차이도 옛것에서 새것으로 읽는다.

- 두 뷰어는 표시 상태 한 벌을 같이 쓰고 조작 도구는 왼쪽에만 있다.
- 카메라는 맞물린다(끌 수 있다). 자세를 그대로 복사하지 않고 물체 경계에 대한 상대 자세로 주고받는다(`viewer-camera-sync.ts`) — 두 버전의 크기가 달라도 구도가 같다. 맞물린 동안 자동 회전은 왼쪽만 돌고 오른쪽은 따라온다.
- 수치 차이 표는 버전 탭 위에 놓인다. 무거워진 값과 가벼워진 값을 색으로 가르고, 치수는 좋고 나쁨이 없어 색을 입히지 않는다. 어느 한쪽 값을 모르면 차이를 말하지 않는다.

### 화면 구성

두 가지 원칙이 화면 전체에 걸려 있다. **정상은 조용하다** — 게시된 자산(대부분)은 카드에 상태 표시가 없고 진행 단계도 한 줄로 줄어든다. 색과 표식은 예외(게시 전·반려·철회·권장 상한 초과)에만 쓴다. **면으로 나눈다** — 레일·미리보기·인스펙터는 한 단 올라온 면(`bg-sidebar`)이고 결과와 뷰어가 놓이는 가운데가 바닥이다. 선을 더 긋기 전에 면의 밝기로 나뉘는지 본다.

화면 구성의 기준은 Unity Asset Manager 웹 대시보드(프로젝트 트리 · 카드 격자 · 옆 미리보기)와 Quixel Bridge(맨 위 검색, 그림이 주인공인 격자, 옆 패널의 미리보기·정보)다. 새 요소를 넣을 때 두 제품에서 같은 일을 어떻게 하는지 먼저 본다.

- 머리말은 화면 이름이 아니라 지금 있는 위치의 길이다(뿌리가 화면 이름). 앞 마디를 누르면 그 위치로 올라간다. 검색은 머리말 가운데에 있다 — 어느 위치에서든 같은 자리다.
- 그 아래 한 줄에 상태 선택·정렬·정렬 방향·결과 수가 왼쪽, CSV·보기 방식이 오른쪽에 놓인다. 정렬 키마다 자연스러운 방향이 있고(이름은 가나다순, 나머지는 큰 것·최근 것이 앞) 방향 버튼은 그것을 뒤집는다 — 값을 모르는 항목은 어느 방향에서도 맨 뒤다.
- 레일은 처리할 일·탐색 계층·컬렉션의 세 묶음뿐이다. 상태는 도구 줄의 선택 상자로 거르고, 카테고리는 계층의 체크박스로 거른다(미리보기·상세의 카테고리를 눌러도 걸리고, 검색도 카테고리를 찾는다).
- 목록은 레일·결과·미리보기의 세 칸이다. 카드(또는 줄)를 한 번 누르면 옆 미리보기에 올라가고, 두 번 누르거나 이름을 누르면 상세로 간다. 이름은 진짜 링크라 새 탭으로도 열린다.
- 미리보기의 그림 아래쪽에 이미지 ↔ 3D 전환이 있다(3D 자산과 배경). 고른 방식은 브라우저마다 기억하고, 이미지로 두면 자산을 넘길 때 파일을 받지 않는다. 이름 옆에는 버전 표식이 붙는다(상세 머리말도 같다).
- 미리보기는 자산의 경로·3D·처리할 일·수명주기 아래에 종류별 상세를 묶음으로 보인다 — 공통 "파일", 3D 자산은 "형상"(권장 상한을 넘은 값은 색과 표식으로), 문서형 자산은 "도면 정보"(도면 번호·리비전·연결된 자산). 경로의 마디와 카테고리는 누르면 목록이 그리로 간다. 고치는 일은 상세로 넘긴다. 되돌리는 걸음밖에 없는 상태에서는 수명주기 버튼을 내지 않는다. 3D 는 자산에 잠시 머문 뒤에 열고(`useSettled`), 큰 파일은 썸네일을 보이다가 요청할 때 연다 — 방향키로 지나치는 자산마다 파일을 받지 않는다.
- 키보드: 미리보기가 열려 있으면 방향키로 앞뒤 자산, Esc 로 닫기. 카드에 초점이 있으면 Space 는 미리보기, Enter 는 상세. 상세에서는 ←/→ 로 목록 순서의 앞뒤 자산(보던 탭 유지). 입력 중이거나 뷰어·대화 상자에 초점이 있으면 가로채지 않는다.
- 카드 보기는 종류별로 묶고(종류를 하나만 고르면 묶지 않는다), 카드는 Unity Asset Manager 의 구성을 따른다 — 옅은 판 안에 그림 판, 그 아래 종류 아이콘·이름 한 줄(게시 전·철회 같은 예외일 때만 상태 점과 글자가 붙는다)과 버전·형식·크기·"얼마 전" 한 줄. 카드는 무엇인지 알아보는 데까지만 말하고 수치는 미리보기와 목록 보기가 맡는다. 미리보기 중인 카드와 선택한 카드는 판의 색과 테두리로 구분한다. 선택·즐겨찾기·더 보기(⋯)는 카드 위에 떠 있고, 더 보기는 우클릭 메뉴를 같은 자리에서 연다. Shift 를 누른 채 고르면 직전 선택부터 범위로 고른다. 씬 배치 수는 목록 보기와 미리보기·상세의 사용처가 맡는다.
- 목록 보기의 열은 보고 있는 종류를 따른다 — 3D 자산은 삼각형·치수·배치, 문서형 자산은 도면 번호·리비전, 배경은 공통 열만. 카테고리 열은 어느 종류에나 있고, 한 종류만 보는 위치에서는 종류 열을 뺀다.
- 여러 개를 고르면 일괄 작업 줄이 나온다 — 상태 전환·카테고리 더하기/빼기·컬렉션·삭제. 메뉴는 고른 자산에 실제로 걸리는 것만 내고 걸리는 수를 적는다(`lib/bulk-selection.ts`). 위치나 필터가 바뀌면 선택을 비운다(보이지 않는 자산에 일괄 작업이 걸리지 않게).
- 일괄 삭제 버튼은 지울 수 있는 것이 없어도 dev 에서는 보인다 — 꺼 두고 이유를 적는다(`countBulkRemovable`). 일부만 지울 수 있으면 확인 창이 남는 수를 적는다.
- 되돌리는 걸음(반려·철회)과 지우기는 한 번 더 묻는다(`asset-confirm-dialog.tsx`). 앞으로 가는 걸음은 묻지 않는다. 쓰이는 버전은 철회 버튼이 꺼지고 그 자리에 이유가 적힌다.
- 자산 하나를 지우는 길은 상세 머리말의 삭제 버튼, 미리보기 아래의 삭제 버튼, 카드 메뉴의 삭제 항목이고 전부 dev 에서만 나온다. 셋이 같은 창(`asset-delete-dialog.tsx`)을 연다 — 쓰이는 자산이면 묻는 대신 왜 지울 수 없는지와 사용처로 가는 길을 보인다.
- 미리보기에 올린 자산이 필터에서 빠져도(검수 목록에서 승인) 패널은 닫히지 않는다. 그 자산이 있던 자리를 기억해 두었다가 이전/다음이 거기서 이어 간다(`stepFromRemembered`).
- 레일의 처리할 일 개수와 상태 선택의 개수는 지금 위치에서 체크한 카테고리까지 건 안에서 센다 — 누르면 그 안에서 걸리기 때문이다.
- 걸린 필터는 결과 위에 칩으로 늘어서고 하나씩 풀 수 있다(계층에서 체크한 카테고리도 칩이다). 계층 위의 위치와 정렬은 칩이 없고 "필터 초기화" 에도 남는다. 계층으로 나타낼 수 없는 상태(종류를 여럿 고른 링크 등)는 보이지 않는 필터가 되지 않게 칩으로 낸다(`active-filters.ts`).
- 레일의 처리할 일과 도구 줄의 상태 선택은 해당 자산이 없는 항목을 내지 않는다(걸어 둔 필터는 0 이어도 남긴다).
- 자산이 없는 위치는 그 종류가 받는 파일 형식을 알리고 등록 버튼을 낸다.
- 결과 수는 지금 위치의 수다. 필터가 걸리면 "위치의 수 중 몇 개" 로 적는다(`countAssetScope`).
- 불러오는 동안에는 카드가 놓일 자리를 미리 잡아 둔다.
- 상세의 정보 탭은 라벨 열·값 열의 속성 표이고, 입력은 올리거나 포커스할 때만 입력란으로 드러난다(`QUIET_FIELD`).
- 통계 탭은 권장 상한이 있는 지표를 상한 대비 막대로 보인다. 넘으면 색과 함께 표식·글자로 알리고, 막대의 바탕도 채움과 같은 색의 옅은 단으로 바뀐다. 크게 적는 숫자에는 고정폭 숫자를 쓰지 않는다(열로 맞출 때만 쓴다).
- 버전 탭은 타임라인이다 — 현재 버전은 채운 마디. 맨 위는 새 버전 올리기 버튼 하나이고(운영에서는 올릴 수 없다는 한 줄), 알아 둘 것(이전 버전은 남는다, 씬은 에디터에서 갱신해야 새 버전을 쓴다)은 목록 아래에 적는다.
- 배치 속성 탭은 씬에 쓰는 종류(모델·지도·배경)에만 있다(`listDetailTabs`). 속성마다 이름·조작 한 줄과 그 값이 무엇을 하는지 한 줄이다.
- 빈 입력 칸은 `—` 로 비어 있음을 적는다(빈 상자로만 보이지 않게).

### 탐색

계층 위의 위치·필터·검색·정렬(방향 포함)·미리보기에 올린 자산과 상세의 탭·보는 버전·비교 버전은 URL 이 단일 소스다. 검색어만 입력 뒤 잠시 있다가 URL 에 쓴다(한글 조합 중 라우터 전환이 입력을 끊지 않게). 보기 방식·즐겨찾기는 브라우저별 설정이라 localStorage 에 둔다. 없어진 자산을 가리키는 즐겨찾기는 라이브러리를 읽는 데 성공했을 때 걷어낸다 — 레일의 개수와 눌렀을 때 보이는 수가 어긋나지 않게.

목록은 화면에 놓인 결과 순서와 쿼리스트링을 sessionStorage 에 남긴다. 상세는 그것으로 이전/다음 자산을 찾고, "라이브러리로" 는 보던 필터 그대로 그 자산을 미리보기에 올린 목록으로 돌아간다. 목록을 거치지 않고 들어온 상세에는 이전/다음이 없다.

### 3D 화면 편집의 팔레트

편집 화면의 모델·맵·배경 탭은 라이브러리의 그 종류 자산이다(`useScenePalette`). 배치 속성에서 숨긴 자산만 빠진다.

- **현재 버전이 게시 상태인 자산만 놓을 수 있다.** 나머지는 흐리게 보이고 상태가 적힌다 — 왜 없는지 찾게 두지 않는다. 이미 놓인 지도는 그대로 뺄 수 있고, 이미 고른 배경은 선택된 채로 보인다.
- 놓는 것은 현재 버전의 파일이고, 파일이 배포 경로에 있어야 한다.
- 모델 탭은 라이브러리의 카테고리로 좁힌다(`palette-category-filter.tsx`). 칩 줄은 "전체" + 고른 카테고리 + 카테고리 검색 버튼이고, 버튼을 누르면 팔레트 오른쪽에 뜨는 목록에서 카테고리를 고른다. 여러 개를 고르면 모두 가진 모델만 남고, 목록의 수는 "이 카테고리까지 걸면 남는 수" 다 — 계층의 카테고리 체크박스와 같은 구현이다(`buildAssetCategoryNodes`·`hasAllAssetCategories`).
- 고른 카테고리는 편집 화면의 상태일 뿐 저장하지 않는다. 라이브러리에서 없어진 카테고리는 풀린다(`pruneScenePaletteCategories`). 맵·배경 탭에는 카테고리 필터가 없다.
- 맵 탭의 타일은 자산당 한 장이다. 놓였는지는 자산 id 로 본다(`getMapPaletteTiles`) — 놓인 버전이 현재 버전과 달라도 같은 자산이다.
- 라이브러리를 읽지 못하면 세 탭이 비고 다시 읽기를 권한다. 이미 놓인 것은 씬이 경로를 들고 있어 그대로 보이고 편집된다.
- 캔버스는 놓을 수 있는 모델 목록이 바뀌면 프리로드한 모델을 비우고 다시 받는다. 그래서 라이브러리를 읽는 동안에는 빈 목록을 주고, 내용이 같으면 같은 배열을 유지한다(`selectPlaceableModels`).

### 씬의 자산 참조와 새 버전 갱신

씬은 놓인 모델·지도·배경마다 파일 경로와 자산 참조(`asset: { id, version }`)를 함께 든다. 지도는 역할(`role`)도 든다.

- **모니터링·3D 플레이는 라이브러리를 읽지 않는다.** 그릴 파일과 지도의 역할이 씬에 있다. 라이브러리가 고장 나도 운영 화면은 그대로다.
- **씬은 현재 버전을 따라가지 않는다.** 라이브러리에서 현재 버전을 바꿔도 씬은 놓을 때의 버전 그대로다. 편집 화면이 팔레트 아래에 "새 버전이 있는 자산" 을 한 줄씩 보이고(`listSceneAssetUpdates`), 갱신을 누르면 **이 씬에 놓인 그 자산이 전부** 새 버전으로 바뀐다(`withSceneAssetVersion`, 되돌리기 한 번). 저장해야 모니터링에 반영된다.
- 갱신은 파일과 버전만 바꾼다. 배치·태그 맵핑·영역은 그대로 두고, 새 파일의 노드 이름이나 원점이 달라졌는지는 화면으로 확인한다.
- 알리는 것은 현재 버전이 게시돼 있고 놓인 버전과 다를 때다. 현재 버전이 더 낮아도(롤백) 알린다.
- 자산 참조가 없는 객체는 라이브러리가 모르는 파일이다. 그대로 렌더되고, 편집 화면이 그런 객체의 수를 한 줄로 알린다. 씬 파일에 참조를 채우는 도구는 `scripts/migrate-scene-asset-refs.mjs` 다.
- 화면 코드가 직접 로드하는 모델도 같은 모양으로 가리킨다(`CODE_ASSETS` — 자산 id·버전·경로). 새 버전을 쓰려면 그 표의 버전과 경로를 고친다. 표가 `library.json` 과 맞는지는 테스트가 고정한다.

### 사용처

자산의 버전마다 그것을 쓰는 씬과 화면 코드를 모은다(`getAssetUsage`). 씬은 자산 참조로, 참조가 없는 객체는 파일 경로로 매칭한다 — 참조를 적기 전의 씬에 놓인 자산을 안 쓰이는 것으로 보지 않는다. 씬 파일을 공유하는 region 은 한 번만 읽고, 읽지 못한 씬은 화면이 알린다. 배경도 사용처에 잡힌다. 화면 코드의 사용은 씬을 읽기 전부터 인덱스에 있다.

## 불변식

- **새 GLTF 로드 경로다 — `extendGltfLoaderWithKtx2` 를 건다.** 뷰어에는 바다가 없어 스텐실 표식은 필요 없다.
- **자산 id 는 바꾸지 않는다.** 씬·코드 자산 표·파일 경로·컬렉션·연결이 id 를 가리킨다.
- **모델·지도·배경의 목록을 코드에 두지 않는다.** 원천은 `library.json` 하나다.
- **배포 파일을 같은 경로에 덮어쓰지 않는다.** 내용이 바뀌면 새 버전이고, 씬과 코드 자산 표는 명시적으로 그 버전으로 옮긴다.
- 씬 객체의 `path` 와 `asset` 은 함께 바꾼다(`withSceneAssetVersion`·`createSceneModel`·`addSceneMap`·`setEnvironment`). 한쪽만 바꾸면 사용처와 새 버전 알림이 어긋난다.
- GLB 경로를 코드에 문자열로 적지 않는다. 코드가 직접 로드하는 모델은 `CODE_ASSETS` 에, 도면은 `CODE_USED_DRAWINGS` 에 올린다 — 올리지 않으면 사용처에 잡히지 않아 지워질 수 있다.
- 파일을 올리고 지우는 스토어 작업은 `canManageFiles` 를 먼저 본다. 철회·삭제는 사용처를 다시 읽은 뒤에 한다(`readUsage`).
- **버전 파일은 덮어쓰지 않는다.** 내용이 바뀌면 새 버전이다.
- 파일 이름에는 이어진 점(`..`)이 없다(`sanitizeAssetFileName` 이 접는다). 경로의 상위 탈출은 조각 단위로 판정한다.
- 저장소 구현을 더하면 "읽은 뒤로 바뀌었으면 쓰지 않는다" 와 "읽지 못한 레코드를 도로 붙인다" 를 같이 구현한다.
- 한 줄 입력(`CommitInput`)의 Esc 는 취소다 — 초점을 빼면서 저장이 불리지 않게 한다.
- Enter 로 그 자리에서 확정하고 입력란을 비우는 입력(카테고리·컬렉션 이름)은 조합 중인 Enter(`nativeEvent.isComposing`)를 확정으로 받지 않는다. 한글은 조합을 끝내는 Enter 와 진짜 Enter 가 따로 와서, 앞의 것에서 확정하면 마지막 글자가 한 번 더 등록된다.
- 카테고리 입력란은 권하는 카테고리로 초점이 옮겨 갈 때 치던 글자를 카테고리로 확정하지 않는다 — 그 글자는 목록을 거르려고 친 것이다.
- 종류를 추가하면 `ASSET_KINDS`·확장자 표(`asset-library-paths.ts`)·`getAllowedAssetKinds`·`getAssetPreviewMode`·`isGeometryAssetKind`/`isDocumentAssetKind`·종류 아이콘(`asset-badges.tsx`)·뷰어 분기(미리보기·상세·비교)·번역(종류 이름, 빈 위치 안내, 받는 형식 안내)·통계 스크립트의 훑는 디렉터리를 함께 고친다. "도면이면" 을 `kind === 'drawing'` 으로 묻지 않고 `isDocumentAssetKind` 로, "형상이 있으면" 을 `isGeometryAssetKind` 로 묻는다 — 둘 다 아닌 종류(배경)가 있어 한쪽의 부정으로 다른 쪽을 대신할 수 없다.
- 스키마 필드의 **이름을 바꾸면** `ASSET_LIBRARY_SCHEMA_VERSION` 을 올리고 sanitize 에 옛 이름 읽기를 둔다. 올리지 않으면 옛 코드(다른 브랜치의 dev 서버)가 새 문서를 읽고 그 필드를 비운 채 저장한다.
- 자산에 붙이는 라벨의 이름은 카테고리(`categories`)다. "태그"·`Tag` 아이콘은 데이터 태그(태그 맵핑·가상 태그)의 것이라 이 슬라이스에서 쓰지 않는다. 카테고리 아이콘은 `Blocks` 다.
- 스키마 필드를 추가하면 `sanitize-asset-library.ts` 를 함께 고친다. 메타데이터 필드면 `AssetMetadataPatch` 와 활동 탭의 필드 이름 번역도.
- 배치 속성 항목을 추가하면 `AssetPlacement`·`sanitizeAssetPlacement`·`isSamePlacement`(`asset-versions.ts`)·팔레트 생성(`scene-palette.ts`)·배치 속성 탭·번역을 함께 고친다. 기본 동작인 값은 저장하지 않는다.
- 경로·파일명 규칙은 `asset-library-paths.ts` 한 곳이다. vite 미들웨어가 이 파일을 직접 import 하므로 의존성 0 을 유지한다.
- `public/asset-library` 는 `vite-plugin-asset-hash.ts` 의 `HASHED_DIRS`·`DEV_WRITTEN_DIRS` 에 들어 있다.
- 배포 경로에 GLB·배경 EXR 이 늘거나 바뀌면 `pnpm assets:stats` 를 다시 돌려 `stats.json` 을 함께 커밋한다.
- 상태 색은 수명주기의 위치만 나타낸다(`ASSET_STATUS_TONE`). 상태는 점과 글자를 함께 쓴다.
- 손이 가야 하는 이유를 추가하면 `ASSET_ATTENTION_KINDS`(급한 순)·`getAssetAttention`·`resolveAttentionTarget`·아이콘 표(`asset-attention.tsx`)·번역을 함께 고친다.
- 목록의 이동(미리보기 이전/다음·범위 선택·상세 이전/다음)은 전부 화면에 놓인 순서 하나를 따른다. 카드 보기의 순서는 종류별 묶음을 이어 붙인 것이다.

## 하지 않기로 한 것

- **읽지 못한 문서를 빈 문서로 받아들이기, 읽기 전의 저장 허용** — 다음 자동 저장이 그 위에 덮어써 내용이 영영 사라진다.
- **자산의 라벨을 "태그" 로 부르기** — 태그 맵핑·가상 태그의 데이터 태그와 이름이 겹쳐, 같은 편집 화면과 같은 파일 안에서 두 뜻이 섞였다.
- **코드 카탈로그(모델·지도·배경 목록을 코드에 두고 라이브러리와 합치기)** — 원천이 둘이 되어 등록한 지도·배경을 에디터에서 쓸 수 없었고, 자산을 더할 때마다 코드를 고쳐야 했다.
- **씬이 자산의 현재 버전을 자동으로 따라가기** — 새 GLB 는 노드 이름·원점이 달라 태그 맵핑·리그·영역이 조용히 깨질 수 있다. 에디터에서 눌러 갱신하고 화면으로 확인한다.
- **한 씬에서 같은 자산을 객체마다 다른 버전으로 두기** — 같은 모델을 두 벌 받게 되고 어느 것이 최신인지 흐려진다. 갱신은 그 자산 전부를 한꺼번에 옮긴다.
- **운영 브라우저에서 자산 등록·새 버전 올리기** — 올린 파일이 그 브라우저에만 남아 씬이 가리킬 수 없고, 사내망에서의 업로드를 피한다.
- **기본 스케일** — 자산은 실척으로 들어온다. 배치 스케일은 씬의 값이다.
- **일괄 작업을 자산마다 저장하기** — 문서 전체를 자산 수만큼 쓴다.
- **최적화 파이프라인을 미들웨어에 다시 구현하기** — 순서(meshopt 가 마지막)와 정책이 두 곳에 있으면 스크립트를 직접 돌린 것과 결과가 갈린다. 스크립트를 그대로 부른다.
- **조선소·분류를 카테고리와 따로 된 속성으로 두기** — 같은 구분을 두 군데에 적게 되고(분류 값은 전부 카테고리와 겹쳤다) 등록할 때마다 둘을 골라야 한다. 조선소는 `okpo`·`philly` 카테고리로 적는다.
- **카테고리로 동작을 가르기(런타임 자산 판정, 팔레트의 고정 묶음 등)** — 카테고리는 사용자가 고칠 수 있다. 코드가 뜻을 아는 카테고리는 없고, 팔레트는 등록된 카테고리를 그대로 보여 고르게 한다.
- **저장 버튼** — 자산 관리는 작업 하나가 곧 한 번의 기록이다. 미저장 상태가 없으니 이탈 경고도 없다.
- **목록에서 GLB 를 열어 통계·썸네일 만들기** — 수십 MB 지도가 목록을 여는 것만으로 내려온다. 통계는 표, 썸네일은 저장된 파일.
- **치수선에 브랜드 주황** — 주황 크레인과 섞여 읽히지 않는다.
- **지오메트리 AABB 를 월드 행렬로 옮겨 크기 재기** — 회전한 메쉬에서 상자가 부푼다. 정점 단위로 잰다.
- **썸네일 촬영 시점을 프레임 수로 짐작** — 캔버스 안은 별도 React 루트라 바깥 상태가 닿는 시점이 프레임과 맞물리지 않아 빈 그림이 찍혔다. 뷰어가 카메라를 맞춘 뒤 알린다.

- **뷰어의 접지 그림자(drei `ContactShadows`)** — 물체 발밑이 아니라 옆에 번진 얼룩으로 그려졌다. 크기가 수 cm 부터 수 km 까지인 자산에 한 설정으로 맞지 않는다.
- **썸네일 바탕의 모눈·카드마다 "씬에 n개" 표시** — 카드 수십 장에 반복되면 그림보다 무늬와 딱지가 먼저 보인다.
- **속성마다 테두리 있는 입력 상자** — 열 줄 넘게 늘어서면 값보다 상자가 먼저 보인다.
- **레일에 종류·상태·카테고리를 따로 줄 세우기** — 같은 자산을 여러 묶음으로 나눠 세면 "어디에 있는가" 가 보이지 않고 레일이 화면보다 길어진다. 위치는 계층 하나가 맡고, 카테고리는 그 계층의 펼친 종류 아래에만 놓는다.
- **카테고리 체크박스의 수를 고정값으로 두기, 체크한 카테고리를 위로 올리기** — 여러 개를 고르면 줄의 수와 누른 결과가 어긋나고, 체크할 때마다 줄이 뛰면 다음 것을 고르기 어렵다.
- **머리말의 화면 설명·종류별 큰 숫자, 카드 크기 조절** — 계층의 개수와 겹치고, 목록을 볼 자리를 줄인다.
- **자산이 없는 종류 마디 숨기기** — CAD 처럼 아직 비어 있는 자리가 어디인지 알 수 없게 된다.
- **게시된 자산마다 초록 점·네 단계 진행 표시** — 거의 모든 자산이 같은 표시를 달면 정작 진행 중인 것이 묻힌다.
- **카드의 그림·글 사이 가로줄, 카드에 수치 여러 줄** — 수십 장이 늘어서면 그림보다 줄과 숫자가 먼저 보인다. 카드는 이름과 상태까지만.
- **결과 수를 라이브러리 전체 대비로 적기** — 위치 안에서는 "57개 중 4개" 가 필터가 걸린 것처럼 읽힌다.
- **미리보기 열림 상태를 로컬 state 에 두기** — URL 과 두 벌이 되면 라우터 전환과 경쟁한다. `?preview=` 하나만 읽는다.
- **마우스 클릭으로 미리보기 접기** — 두 번 누름의 첫 클릭이 올리고 둘째 클릭이 내려 화면이 깜빡인다. 접기는 키보드(Space)와 닫기 버튼만.
- **비교 뷰어의 카메라 자세 그대로 복사** — 크기가 다른 두 버전에서 한쪽이 화면 밖으로 나간다.
- **높이 치수 꼬리표를 오른쪽 세로 모서리에 두기** — 납작하고 긴 물체에서 깊이 꼬리표와 겹친다.

## 미룬 것

- 옛 배포 경로(`/models` 등)의 버전 1 파일을 라이브러리 디렉터리로 옮기기 — 지금은 버전 1 만 옛 경로에 있다.
- 갱신할 때 새 파일에 없는 노드를 가리키는 태그 맵핑·리그·영역을 알리기.
- 모델의 원점 복원·거리별 LOD·정적 병합을 등록할 때 자동으로 하기 — 지금은 올리기 전에 스크립트로 파일을 가공한다(`docs/agents/assets-glb.md`).
- 쓰이지 않는 옛 버전의 파일 정리 — 지금은 게시된 적 있는 버전을 전부 보관한다.
- 자산 서버 — HTTP 저장소 구현, 권한(역할별 승인), 파일 잠금, 다단계 승인. 지금의 충돌 처리는 "쓰지 않고 다시 읽게 한다" 까지이고 변경을 합치지는 않는다.
- 목록 가상 스크롤(자산이 수천 개일 때), 여러 파일 한 번에 등록, 되돌리기(undo), 컬렉션 이름 바꾸기 화면.
- dev 저장 미들웨어의 접근 제한 — dev 서버가 사내망에 열려 있어(`host: true`) 같은 망에서 문서·파일을 쓸 수 있다. 인증·출처 확인·본문 크기 제한이 없다.
- CAD 원본(DWG·DXF·STEP·IGES) 미리보기와 GLB 변환, 도면 마크업.
- 카테고리 이름 일괄 바꾸기, 카테고리가 없는 자산만 골라 보기, 카테고리 가운데 "하나라도" 가진 자산 보기.
- 3D 위 주석(카메라 시점이 함께 저장되는 검토 코멘트), 반려 사유 입력, 저장된 사용자 정의 보기, 노드 트리·격리 보기.
