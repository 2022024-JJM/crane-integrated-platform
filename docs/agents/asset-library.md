# 3D 자산 라이브러리 — 자산 목록·미리보기·상세 뷰어·버전 비교·상태·사용처, 서버 없는 저장

> 이 문서는 현재 상태만 적는다. 갱신은 덧붙이기가 아니라 덮어쓰기. 날짜·경위·사라진 UI 는 쓰지 않는다.

조선소(옥포·필리)에서 쓰는 3D 모델·지도·배경·도면·CAD 원본을 한곳에서 찾고 버전과 상태를 관리하는 전사 공용 화면이다. region 하위가 아닌 최상위 경로(`/asset-library`, `/asset-library/:assetId`)에 있고 사이드바 "자산" 그룹에서 들어간다. GLB 를 만들고 압축하는 파이프라인은 `docs/agents/assets-glb.md`.

## 동작

### 자산의 두 출처

- **builtin** — 코드 카탈로그(`sceneModelCatalog`·`sceneMapCatalog`·`sceneEnvironmentCatalog`)와 카탈로그 밖 배포 자산 표에서 온다. 카탈로그 id 가 곧 자산 id 다. 카탈로그가 정체성(id·종류·파일 경로·기본 스케일)의 원천이고 `library.json` 이 메타데이터(이름·설명·태그·상태·추가 버전·이력·썸네일)의 원천이다. 카탈로그에 항목을 추가하면 문서를 고치지 않아도 라이브러리에 나타나고, 뺀 항목은 문서에 남아 있어도 사라진다. 지울 수 없다. 새로 나타난 모델·지도는 카탈로그의 분류를 첫 태그로 받아 계층의 체크박스 아래에 놓인다 — 문서에 이미 있는 자산은 문서의 태그가 이긴다.
- **user** — 이 화면에서 등록한 자산. 버전 1(초안)로 시작하고 지울 수 있다(파일까지).

### 종류

`model`·`map` 은 씬에 놓는 3D 자산(GLB)이다(`isGeometryAssetKind`) — 기하 통계·권장 상한·사용처·기본 스케일은 이 둘에만 있다. `environment` 는 씬의 배경(등장방형 파노라마 EXR)이다. 씬에 놓는 것이 아니라 씬이 `environmentId` 로 고르는 것이라 배치 수가 없고 "미사용" 도 판정하지 않는다. `drawing`(화면에서 보는 도면: PDF·SVG·그림)과 `cad`(CAD 원본: `ASSET_CAD_EXTENSIONS`)는 문서형 자산이고(`isDocumentAssetKind`) 도면 번호·리비전을 가진다. 종류는 파일 확장자가 정한다(`getAllowedAssetKinds`) — GLB 만 모델·지도 중에서 고른다. CAD 원본은 미리보기 없이 보관·버전 관리만 한다.

배포된 배경은 씬 배경 카탈로그의 항목이다. 씬은 카탈로그의 파일을 쓴다 — 이 화면에서 등록한 배경과 새 버전은 씬에 적용되지 않는다(버전 탭과 사용처 탭이 그렇게 알린다).

### 탐색 계층

자산이 "어디에 있는가" 는 종류(모델·지도·배경·도면·CAD)다. 그 아래의 세부 분류는 전부 태그가 맡는다 — 실내·실외, 크레인·블록, 옥포·필리 같은 구분을 따로 된 속성으로 두지 않는다. 계층은 저장된 구조가 아니라 자산의 속성(`kind`·`tags`)에서 그때그때 만든다.

- 종류 줄은 자산이 없어도 전부 나온다(그 자리에 무엇을 둘 수 있는지 보인다). 누르면 그 종류 전부를 보고 고른 태그는 풀린다.
- 종류 아래에 그 종류의 자산이 가진 태그가 체크박스로 놓인다. 펼친 종류 아래에만 나오고, 순서는 그 종류에서 많이 쓰인 순으로 고정이다 — 체크해도 줄이 자리를 바꾸지 않는다. 대소문자만 다른 태그는 한 줄이다.
- 여러 개를 체크하면 **모두 가진** 자산만 남는다(`queryAssets` 와 같은 규칙). 그래서 체크 안 한 태그의 수는 "지금 고른 것에 이 태그까지 걸면 남는 수" 이고, 0 이면 고를 수 없다.
- 줄의 수는 그 줄을 누른 탐색 결과의 수와 같다(테스트가 고정한다).
- 다른 종류의 태그를 체크하면 그 종류로 옮겨 가며 그 태그 하나로 새로 시작한다. 전체를 보는 중이면 고른 태그를 들고 그 종류로 들어간다(`toggleAssetScopeTag`).
- 계층 위의 위치(`AssetScope`)는 종류까지다. 화면 머리말이 그 길을 적는다. 체크한 태그는 검색·상태와 같은 **필터**라 결과 위에 칩으로 나오고 "필터 초기화" 에 풀린다 — 위치는 남는다.
- 등록할 때 보고 있던 종류와 같은 종류의 파일이면 거기서 체크해 둔 태그로 시작한다. 태그를 붙이는 자리(등록·정보 탭)는 같은 종류에서 이미 쓰는 태그를 권한다(`listAssetKindTags`) — 철자가 갈리면 체크박스가 둘로 나뉜다.

### 버전·상태

- 버전 파일은 불변이고 경로에 자산 id 와 버전 번호가 들어간다. dev 미들웨어는 이미 있는 버전 경로에 쓰지 않는다.
- 버전은 추가가 기본이다. 지울 수 있는 것은 **게시된 적 없는 버전(초안·반려)** 뿐이고(`canRemoveAssetVersion`), 현재 버전과 마지막 남은 버전은 지울 수 없다. 지운 번호는 다시 쓰지 않는다 — 다음 번호는 이력까지 보고 정한다.
- 메타데이터 수정은 버전을 만들지 않는다. 파일을 바꾸면 새 버전(초안)이 되고 현재 버전 포인터는 그대로다 — 사용자가 "현재 버전으로 지정" 으로 옮긴다. 롤백도 포인터 이동이다.
- 상태는 **버전 단위**이고 전이는 `asset-versions.ts` 의 표만 따른다. 철회·반려된 버전은 현재가 될 수 없다.
- 문서형 자산(도면·CAD)은 버전 번호와 별개로 리비전 표기(`revision`)와 도면 번호(`drawingNo`)를 가진다.
- 변경 함수는 바뀐 것이 없으면 입력 참조를 그대로 돌려주고, 스토어는 그때 저장하지 않는다.
- 이력은 자산마다 상한까지 남는다. 같은 사람이 짧은 시간 안에 이어 고친 메타데이터는 한 줄로 묶는다. 자동 생성 썸네일은 이력에 남기지 않는다.

### 처리할 일

목록의 대부분은 손 갈 데 없는 자산이다. 손이 가야 하는 이유(검토 대기·반려·검토 요청 전·새 버전 있음·권장 상한 초과·미사용)를 `getAssetAttention` 한 곳에서 판정하고, 레일의 "처리할 일" 개수·카드의 표식·미리보기와 상세의 안내·`attn` 필터가 전부 이 판정을 쓴다.

- "미사용" 은 사용처를 읽은 뒤에만 판정한다. 도면·CAD·배경과 런타임 자산(코드가 직접 로드)은 놓인 곳이 없어도 미사용이 아니다. 런타임 자산은 "카탈로그에 없는 배포 자산" 으로 가린다 — 태그로 묻지 않는다.
- 카드에는 가장 급한 이유 하나만 붙고, 문제없는 자산에는 아무것도 붙지 않는다.
- 안내 줄을 누르면 그 일을 처리하는 버전·탭으로 간다(`resolveAttentionTarget`). 이미 그 자리에 와 있으면 안내하지 않는다.
- "새 버전 있음" 은 검토를 통과한(승인·게시) 새 버전이 아직 현재로 지정되지 않았을 때만이다. 검토 전·검토 중인 새 버전은 그 상태의 이유가 따로 알린다 — 같은 버전에 이유가 둘 붙지 않는다.
- 미리보기는 현재 버전이 아니라 **지금 손이 가야 하는 버전**을 보여 준다(`pickPreviewVersion` — 걸린 필터의 대상 버전 → 검토 중인 버전 → 현재 버전). 한 자산을 보는 동안에는 버전을 바꿔치지 않아, 승인 → 게시 → 현재 버전으로 지정을 패널에서 이어서 할 수 있다.

### 수명주기

상태는 드롭다운 속에 두지 않고 길(초안 → 검토 중 → 승인됨 → 게시됨)로 펼쳐 지금 위치와 다음 걸음을 함께 보인다(`asset-lifecycle.tsx`). 반려·철회는 길 위의 한 지점에 멈춰 선 상태로 그린다. 앞으로 가는 걸음은 넓은 주 버튼, 되돌리는 걸음(반려·철회)은 작은 보조 버튼이다. 게시된 버전은 길을 다시 늘어놓지 않고 한 줄로 적으며, 되돌리는 걸음(철회)은 머리 줄에 작게 둔다. 미리보기 패널과 상세 인스펙터 맨 위(어느 탭에서도 보인다)에 있다.

### 저장 — 서버 없이

화면은 `AssetLibraryRepository` 만 안다. 스토어는 바꿀 때마다 자동 저장하고(저장 버튼 없음), 저장을 한 줄로 세워 실행 시점의 최신 상태를 쓴다. 실패하면 메모리 상태를 유지하고 재시도를 권한다.

저장은 문서를 통째로 쓴다. 그래서 다음 네 가지를 지킨다.

- **다 읽은 뒤에만 고치고 쓴다.** 읽는 중·읽기 실패 상태의 메모리는 빈 목록이라, 그때 쓰면 문서가 빈 것으로 덮인다. 스토어의 모든 변경이 `status === 'ready'` 를 먼저 본다.
- **읽은 뒤로 다른 곳에서 바뀌었으면 쓰지 않는다.** dev 는 읽은 글자의 지문(`hashAssetLibraryText`)을 헤더로 보내 미들웨어가 지금 파일과 견주고, 브라우저 저장소는 봉투의 `revision` 을 견준다. 다르면 `AssetLibraryConflictError` → `saveState: 'conflict'`. 다시 읽어야(`load({ force: true })`) 풀리고, 그 전까지는 쓰지 않는다. 다시 읽으면 저장 못 한 변경은 버려진다.
- **읽지 못한 것을 지우지 않는다.** 모양이 틀리거나 이 앱보다 새 스키마의 문서는 빈 문서로 열지 않고 읽기 실패로 알린다. 방어를 통과하지 못한 개별 레코드는 저장소가 원본 그대로 들고 있다가 저장할 때 도로 붙인다.
- **문서 저장이 성공한 뒤에만 파일을 지운다.** 자산·버전 삭제는 저장에 실패하면 화면을 지우기 전으로 되돌리고 파일을 건드리지 않는다.

여러 자산을 한 번에 고치는 일(일괄 작업)은 한 번만 저장한다(`updateManyMetadata`·`transitionManyStatus`·`removeManyAssets`).

- **dev** — 문서는 `POST /__dev/asset-library` 로 `public/asset-library/library.json` 에, 파일은 `/file?key=` 로 `files/<id>/v<N>/<name>`·`thumbnails/<id>.png` 에 쓴다. 커밋하면 배포의 기준값이 된다.
- **운영** — 미들웨어가 없어 문서는 localStorage 봉투에, 파일은 IndexedDB 에 둔다. **그 브라우저에만 남는다**(화면이 그렇게 알린다). 봉투의 `baseVersion` 이 현재 배포 문서의 해시와 다르면 배포본이 이긴다(씬·가상 태그와 같은 규칙).
- 브라우저 저장소의 키는 배포 파일과 같은 상대 경로다. 서버가 생기면 같은 인터페이스의 구현을 하나 더 만들어 `getAssetLibraryRepository` 의 분기만 바꾼다.

### 등록 시 모델 최적화

모델(GLB)을 등록하거나 새 버전을 올릴 때 최적화해 저장할 수 있다(기본 켜짐). 파이프라인은 `scripts/optimize-glb.mjs` 하나다 — dev 미들웨어가 그 스크립트를 `--single <입력> <출력>` 로 자식 프로세스에서 돌린다(`optimizeGlbBuffer`). 순서·정책은 `docs/agents/assets-glb.md`.

- dev 서버에서만 된다(`AssetLibraryRepository.canOptimize`). 운영(브라우저 저장)에서는 옵션이 나오지 않는다.
- 모델만이다. 지도는 타일·LOD 를 만드는 전용 파이프라인(`pnpm optimize:map`)이 있어 여기서 건드리지 않는다.
- 저장되는 것은 최적화한 파일이고, 올린 원본은 `assets-src/asset-library/<id>/v<N>/<name>` 에 둔다(`ASSET_LIBRARY_ORIGINALS_DIR` — `assets-src/models` 와 같은 역할). 자산·버전을 지우면 원본도 지운다.
- 버전의 `sizeBytes` 는 저장된 파일의 크기, `originalSizeBytes` 는 올린 원본의 크기다(있으면 최적화한 버전). `contentHash` 는 **원본**의 해시다 — 같은 원본을 다시 올리는 것을 알아보는 값이라.
- 최적화가 실패하거나 결과가 원본보다 작지 않으면 원본 그대로 저장한다. 등록을 막지 않고, 화면이 그렇게 알린다.

### 통계

- 배포 파일의 크기·삼각형 수 등은 `pnpm assets:stats` 가 `stats.json` 에 미리 뽑아 둔다. 목록은 이 표로 표시·정렬하므로 GLB 를 열지 않는다. GLB 가 아닌 파일(배경 EXR·도면)은 크기와 해시만 적는다.
- 표의 항목은 **지금 배포된 파일과 해시가 같을 때만** 쓴다(자산 해시 매니페스트와 비교) — 낡은 항목은 비운다. `pnpm assets:stats --check` 가 낡은 항목을 보고한다.
- 이 화면에서 올린 파일은 뷰어가 처음 열 때 재서 버전 레코드에 채운다.
- 스크립트와 브라우저 측정은 같은 기준이다: LOD 사본(`lod > 0`)은 렌더 기준에서 빼고, 메쉬는 프리미티브 단위로 센다. 노드 수만 기준이 다르다(glTF 노드 vs three 객체) — 그래서 상세 화면은 저장된 값이 있으면 그것을 쓴다.
- 권장 상한(`ASSET_BUDGET`)은 `scripts/scene-perf-report.mjs` 의 모델 단위 경고 기준과 같은 값이다. 초과해도 등록을 막지 않는다.

### 뷰어

- 모니터링 씬 뷰어(`ThreeSceneViewer`)를 쓰지 않는다 — 그쪽은 지도 위를 나는 카메라고 여기는 물체 하나를 돌려 보는 카메라다. 캔버스는 `frameloop="demand"` 이고 자동 회전을 켠 동안만 계속 그린다.
- 조명은 방향광 + 절차적 반사 환경(three `RoomEnvironment`)이다. 금속·도장면은 비칠 것이 있어야 재질로 읽히고, 폐쇄망이라 HDRI 프리셋을 받을 수 없다.
- 바닥 격자는 멀어질수록 흐려지는 무한 격자(drei `Grid`)다. 칸 크기는 물체 크기에서 고른다(`pickGridStep`).
- 뷰어 위 조작은 배경·테마와 무관한 어두운 유리판 위에 놓고, 켜진 상태는 흰 판으로 나타낸다. 브랜드 주황은 탭 밑줄·선택 표시에만 쓴다.
- 치수는 정점 단위로 잰 경계 상자에 자산의 기본 스케일을 곱한 값이다. 씬 단위가 m 가 아닌 씬(`dock-in`)의 자산은 실제 길이와 다르다.
- 치수선·라벨은 배경과 대비되는 무채색이다. 조선소 크레인은 주황·노랑 도장이 많아 브랜드 주황은 물체와 섞인다.
- 뷰 모드는 메쉬의 material 슬롯만 바꿨다가 되돌린다(원본 머티리얼은 캐시와 공유).
- LOD 단계 미리보기는 최상위 캐리어만 켜고 끈다(`docs/agents/assets-glb.md` 와 같은 계약).
- 배경은 따로 둔 파노라마 뷰어(`asset-environment-viewer.tsx`)로 본다. 씬과 같은 방식으로 EXR 을 `scene.background` 에 걸고 렌더러의 톤매핑을 거치며, 카메라는 제자리에서 돌기만 한다(끌면 그림이 손을 따라온다). 시작 시점은 파노라마의 한가운데(+X)다. 화면을 떠나면 그 파일의 로더 캐시를 놓는다.
- 배경의 썸네일은 처음 보이는 시점의 가운데를 가로로 긴 비율로 자른 불투명 그림이고(`centerCropRect`), 목록에서는 받침 위에 띄우지 않고 자리를 채운다.
- 썸네일은 투명 배경 PNG 이고, 물체가 차지한 영역만 잘라 정사각에 채운다(`lib/thumbnail-crop.ts`) — 가는 물체도 목록에서 같은 크기로 보인다. 원천 순서는 저장된 썸네일 → 배포된 정적 썸네일(`/previews/{id}.png`, 매니페스트에 있을 때만) → 그림 도면은 파일 자체 → 종류 아이콘. 썸네일이 없는 자산은 처음 열렸을 때 한 번 자동으로 찍는다. 배포된 정적 썸네일은 작고 물체가 화면 한쪽에 몰려 있어, 카탈로그 자산도 저장된 썸네일을 갖춰 두었다 — 정적 썸네일은 그것이 없을 때의 대비책이다.
- 뷰어 아래 표제란은 지금 올라온 파일(파일명·버전·크기·치수·삼각형)만 적는다. 이름과 상태는 머리말과 진행 단계가 말한다.
- 화면을 떠나면 그 파일의 GLTF 캐시를 놓는다.
- 표시 상태(뷰 모드·배경·격자·치수·자동 회전)는 뷰어가 직접 들거나 바깥이 넘긴다(`display`). 조작 도구는 `toolbar` 로 전부·좁은 자리용·없음을 고른다.
- 캔버스는 이벤트를 걸 요소를 직접 받는다(`eventSource`). R3F 는 만들어진 뒤 비동기로 이벤트를 거는데, 그 사이 뷰어가 사라지면 없는 요소에 걸다 던진다.

### 버전 비교

상세에서 보고 있는 버전과 다른 버전 하나를 나란히 놓는다(`?compare=`). 어느 쪽을 보고 있었든 왼쪽이 옛 버전, 오른쪽이 새 버전이고 차이도 옛것에서 새것으로 읽는다.

- 두 뷰어는 표시 상태 한 벌을 같이 쓰고 조작 도구는 왼쪽에만 있다.
- 카메라는 맞물린다(끌 수 있다). 자세를 그대로 복사하지 않고 물체 경계에 대한 상대 자세로 주고받는다(`viewer-camera-sync.ts`) — 두 버전의 크기가 달라도 구도가 같다. 맞물린 동안 자동 회전은 왼쪽만 돌고 오른쪽은 따라온다.
- 수치 차이 표는 버전 탭 위에 놓인다. 무거워진 값과 가벼워진 값을 색으로 가르고, 치수는 좋고 나쁨이 없어 색을 입히지 않는다. 어느 한쪽 값을 모르면 차이를 말하지 않는다.

### 화면 구성

두 가지 원칙이 화면 전체에 걸려 있다. **정상은 조용하다** — 게시된 자산(대부분)은 카드에 상태 표시가 없고 진행 단계도 한 줄로 줄어든다. 색과 표식은 예외(게시 전·반려·철회·권장 상한 초과)에만 쓴다. **면으로 나눈다** — 레일·미리보기·인스펙터는 한 단 올라온 면(`bg-sidebar`)이고 결과와 뷰어가 놓이는 가운데가 바닥이다. 선을 더 긋기 전에 면의 밝기로 나뉘는지 본다.

화면 구성의 기준은 Unity Asset Manager 웹 대시보드(프로젝트 트리 · 카드 격자 · 옆 미리보기)와 Quixel Bridge(맨 위 검색, 그림이 주인공인 격자, 옆 패널의 미리보기·정보)다. 새 요소를 넣을 때 두 제품에서 같은 일을 어떻게 하는지 먼저 본다.

- 머리말은 화면 이름이 아니라 지금 있는 위치의 길이다(뿌리가 화면 이름). 앞 마디를 누르면 그 위치로 올라간다. 검색은 머리말 가운데에 있다 — 어느 위치에서든 같은 자리다.
- 그 아래 한 줄에 상태 선택·정렬·정렬 방향·결과 수가 왼쪽, 보기 방식·CSV 가 오른쪽에 놓인다. 정렬 키마다 자연스러운 방향이 있고(이름은 가나다순, 나머지는 큰 것·최근 것이 앞) 방향 버튼은 그것을 뒤집는다 — 값을 모르는 항목은 어느 방향에서도 맨 뒤다.
- 레일은 처리할 일·탐색 계층·컬렉션의 세 묶음뿐이다. 상태는 도구 줄의 선택 상자로 거르고, 태그는 계층의 체크박스로 거른다(미리보기·상세의 태그를 눌러도 걸리고, 검색도 태그를 찾는다).
- 목록은 레일·결과·미리보기의 세 칸이다. 카드(또는 줄)를 한 번 누르면 옆 미리보기에 올라가고, 두 번 누르거나 이름을 누르면 상세로 간다. 이름은 진짜 링크라 새 탭으로도 열린다.
- 미리보기의 그림 아래쪽에 이미지 ↔ 3D 전환이 있다(3D 자산과 배경). 고른 방식은 브라우저마다 기억하고, 이미지로 두면 자산을 넘길 때 파일을 받지 않는다. 이름 옆에는 버전 표식이 붙는다(상세 머리말도 같다).
- 미리보기는 자산의 경로·3D·처리할 일·수명주기 아래에 종류별 상세를 묶음으로 보인다 — 공통 "파일", 3D 자산은 "형상"(권장 상한을 넘은 값은 색과 표식으로), 문서형 자산은 "도면 정보"(도면 번호·리비전·연결된 자산). 경로의 마디와 태그는 누르면 목록이 그리로 간다. 고치는 일은 상세로 넘긴다. 되돌리는 걸음밖에 없는 상태에서는 수명주기 버튼을 내지 않는다. 3D 는 자산에 잠시 머문 뒤에 열고(`useSettled`), 큰 파일은 썸네일을 보이다가 요청할 때 연다 — 방향키로 지나치는 자산마다 파일을 받지 않는다.
- 키보드: 미리보기가 열려 있으면 방향키로 앞뒤 자산, Esc 로 닫기. 카드에 초점이 있으면 Space 는 미리보기, Enter 는 상세. 상세에서는 ←/→ 로 목록 순서의 앞뒤 자산(보던 탭 유지). 입력 중이거나 뷰어·대화 상자에 초점이 있으면 가로채지 않는다.
- 카드 보기는 종류별로 묶고(종류를 하나만 고르면 묶지 않는다), 카드는 Unity Asset Manager 의 구성을 따른다 — 옅은 판 안에 그림 판, 그 아래 종류 아이콘·이름 한 줄(게시 전·철회 같은 예외일 때만 상태 점과 글자가 붙는다)과 버전·형식·크기·"얼마 전" 한 줄. 카드는 무엇인지 알아보는 데까지만 말하고 수치는 미리보기와 목록 보기가 맡는다. 미리보기 중인 카드와 선택한 카드는 판의 색과 테두리로 구분한다. 선택·즐겨찾기·더 보기(⋯)는 카드 위에 떠 있고, 더 보기는 우클릭 메뉴를 같은 자리에서 연다. Shift 를 누른 채 고르면 직전 선택부터 범위로 고른다. 씬 배치 수는 목록 보기와 미리보기·상세의 사용처가 맡는다.
- 목록 보기의 열은 보고 있는 종류를 따른다 — 3D 자산은 삼각형·치수·배치, 문서형 자산은 도면 번호·리비전, 배경은 공통 열만. 태그 열은 어느 종류에나 있고, 한 종류만 보는 위치에서는 종류 열을 뺀다.
- 여러 개를 고르면 일괄 작업 줄이 나온다 — 상태 전환·태그 더하기/빼기·컬렉션·삭제. 메뉴는 고른 자산에 실제로 걸리는 것만 내고 걸리는 수를 적는다(`lib/bulk-selection.ts`). 위치나 필터가 바뀌면 선택을 비운다(보이지 않는 자산에 일괄 작업이 걸리지 않게).
- 되돌리는 걸음(반려·철회)과 지우기는 한 번 더 묻는다(`asset-confirm-dialog.tsx`). 앞으로 가는 걸음은 묻지 않는다. 씬에 놓인 자산을 지울 때는 놓인 수를 알린다.
- 미리보기에 올린 자산이 필터에서 빠져도(검수 목록에서 승인) 패널은 닫히지 않는다. 그 자산이 있던 자리를 기억해 두었다가 이전/다음이 거기서 이어 간다(`stepFromRemembered`).
- 레일의 처리할 일 개수와 상태 선택의 개수는 지금 위치에서 체크한 태그까지 건 안에서 센다 — 누르면 그 안에서 걸리기 때문이다.
- 걸린 필터는 결과 위에 칩으로 늘어서고 하나씩 풀 수 있다(계층에서 체크한 태그도 칩이다). 계층 위의 위치와 정렬은 칩이 없고 "필터 초기화" 에도 남는다. 계층으로 나타낼 수 없는 상태(종류를 여럿 고른 링크 등)는 보이지 않는 필터가 되지 않게 칩으로 낸다(`active-filters.ts`).
- 레일의 처리할 일과 도구 줄의 상태 선택은 해당 자산이 없는 항목을 내지 않는다(걸어 둔 필터는 0 이어도 남긴다).
- 자산이 없는 위치는 그 종류가 받는 파일 형식을 알리고 등록 버튼을 낸다.
- 결과 수는 지금 위치의 수다. 필터가 걸리면 "위치의 수 중 몇 개" 로 적는다(`countAssetScope`).
- 불러오는 동안에는 카드가 놓일 자리를 미리 잡아 둔다.
- 상세의 정보 탭은 라벨 열·값 열의 속성 표이고, 입력은 올리거나 포커스할 때만 입력란으로 드러난다(`QUIET_FIELD`).
- 통계 탭은 권장 상한이 있는 지표를 상한 대비 막대로 보인다. 넘으면 색과 함께 표식·글자로 알리고, 막대의 바탕도 채움과 같은 색의 옅은 단으로 바뀐다. 크게 적는 숫자에는 고정폭 숫자를 쓰지 않는다(열로 맞출 때만 쓴다).
- 버전 탭은 타임라인이다 — 현재 버전은 채운 마디. 맨 위는 새 버전 올리기 버튼 하나이고, 알아 둘 것(이전 버전은 남는다, 씬에 반영되는 방식)은 목록 아래에 적는다.
- 빈 입력 칸은 `—` 로 비어 있음을 적는다(빈 상자로만 보이지 않게).

### 탐색

계층 위의 위치·필터·검색·정렬(방향 포함)·미리보기에 올린 자산과 상세의 탭·보는 버전·비교 버전은 URL 이 단일 소스다. 검색어만 입력 뒤 잠시 있다가 URL 에 쓴다(한글 조합 중 라우터 전환이 입력을 끊지 않게). 보기 방식·즐겨찾기는 브라우저별 설정이라 localStorage 에 둔다. 없어진 자산을 가리키는 즐겨찾기는 라이브러리를 읽는 데 성공했을 때 걷어낸다 — 레일의 개수와 눌렀을 때 보이는 수가 어긋나지 않게.

목록은 화면에 놓인 결과 순서와 쿼리스트링을 sessionStorage 에 남긴다. 상세는 그것으로 이전/다음 자산을 찾고, "라이브러리로" 는 보던 필터 그대로 그 자산을 미리보기에 올린 목록으로 돌아간다. 목록을 거치지 않고 들어온 상세에는 이전/다음이 없다.

### 3D 화면 편집의 팔레트

편집 화면의 모델 팔레트는 카탈로그를 라이브러리와 합친 목록이다(`buildScenePaletteModels`).

- 이름·썸네일은 라이브러리를 따른다. 카탈로그 자산의 파일 경로와 기본 스케일은 카탈로그 그대로다.
- 팔레트의 묶음(실내·실외)은 `indoor`·`outdoor` 태그가 정한다(`resolvePaletteGroup` — 둘 다 있으면 앞에 적힌 것). 그 태그가 없으면 카탈로그 자산은 카탈로그의 분류로, 등록한 자산은 빈 묶음으로 간다. 묶음을 옮기려면 태그를 바꾼다.
- **현재 버전이 게시 상태인 자산만 놓을 수 있다.** 나머지는 팔레트에 흐리게 보이고 상태가 적힌다 — 왜 없는지 찾게 두지 않는다.
- 이 화면에서 등록한 모델도 팔레트에 나온다. 놓는 것은 현재 버전의 파일이고, 파일이 배포 경로(dev 저장)에 있어야 한다 — 브라우저에만 있는 파일은 씬이 가리킬 경로가 없어 놓을 수 없다.
- 씬은 자산을 파일 경로로 참조한다. 이미 놓은 것은 놓을 때의 파일 그대로이고, 현재 버전을 바꿔도 따라오지 않는다.
- 라이브러리를 읽지 못하면 카탈로그 그대로 전부 놓을 수 있다 — 라이브러리가 고장 나도 편집은 멈추지 않는다.
- 캔버스는 놓을 수 있는 목록이 바뀌면 프리로드한 모델을 비우고 다시 받는다. 그래서 라이브러리를 읽는 동안에는 빈 목록을 주고, 내용이 같으면 같은 배열을 유지한다(`selectPlaceableCatalog`).

### 사용처

씬 JSON 이 자산을 파일 경로로 참조하므로 매칭도 경로로 한다. 씬 파일을 공유하는 region 은 한 번만 읽는다. 읽지 못한 씬은 화면이 알린다. 카탈로그 밖 배포 자산(코드가 직접 로드)은 사용처가 비어 보여도 쓰이는 자산이다.

## 불변식

- **새 GLTF 로드 경로다 — `extendGltfLoaderWithKtx2` 를 건다.** 뷰어에는 바다가 없어 스텐실 표식은 필요 없다.
- **자산 id 는 바꾸지 않는다.** 파일 경로·컬렉션·연결이 id 를 가리킨다. builtin 의 id 는 카탈로그 id 이므로 카탈로그 id 를 바꾸면 저장된 메타데이터가 떨어져 나간다.
- **버전 파일은 덮어쓰지 않는다.** 내용이 바뀌면 새 버전이다.
- 파일 이름에는 이어진 점(`..`)이 없다(`sanitizeAssetFileName` 이 접는다). 경로의 상위 탈출은 조각 단위로 판정한다.
- 저장소 구현을 더하면 "읽은 뒤로 바뀌었으면 쓰지 않는다" 와 "읽지 못한 레코드를 도로 붙인다" 를 같이 구현한다.
- 한 줄 입력(`CommitInput`)의 Esc 는 취소다 — 초점을 빼면서 저장이 불리지 않게 한다.
- 종류를 추가하면 `ASSET_KINDS`·확장자 표(`asset-library-paths.ts`)·`getAllowedAssetKinds`·`getAssetPreviewMode`·`isGeometryAssetKind`/`isDocumentAssetKind`·종류 아이콘(`asset-badges.tsx`)·뷰어 분기(미리보기·상세·비교)·번역(종류 이름, 빈 위치 안내, 받는 형식 안내)·통계 스크립트의 훑는 디렉터리를 함께 고친다. "도면이면" 을 `kind === 'drawing'` 으로 묻지 않고 `isDocumentAssetKind` 로, "형상이 있으면" 을 `isGeometryAssetKind` 로 묻는다 — 둘 다 아닌 종류(배경)가 있어 한쪽의 부정으로 다른 쪽을 대신할 수 없다.
- 스키마 필드를 추가하면 `sanitize-asset-library.ts` 를 함께 고친다. 메타데이터 필드면 `AssetMetadataPatch` 와 활동 탭의 필드 이름 번역도.
- 경로·파일명 규칙은 `asset-library-paths.ts` 한 곳이다. vite 미들웨어가 이 파일을 직접 import 하므로 의존성 0 을 유지한다.
- `public/asset-library` 는 `vite-plugin-asset-hash.ts` 의 `HASHED_DIRS`·`DEV_WRITTEN_DIRS` 에 들어 있다.
- GLB·배경 EXR 을 반입·교체하면 `pnpm assets:stats` 를 다시 돌려 `stats.json` 을 함께 커밋한다.
- 카탈로그 밖에서 코드가 직접 로드하는 GLB 를 추가하면 `builtin-extra-assets.ts` 에도 올린다.
- 상태 색은 수명주기의 위치만 나타낸다(`ASSET_STATUS_TONE`). 상태는 점과 글자를 함께 쓴다.
- 손이 가야 하는 이유를 추가하면 `ASSET_ATTENTION_KINDS`(급한 순)·`getAssetAttention`·`resolveAttentionTarget`·아이콘 표(`asset-attention.tsx`)·번역을 함께 고친다.
- 목록의 이동(미리보기 이전/다음·범위 선택·상세 이전/다음)은 전부 화면에 놓인 순서 하나를 따른다. 카드 보기의 순서는 종류별 묶음을 이어 붙인 것이다.

## 하지 않기로 한 것

- **읽지 못한 문서를 빈 문서로 받아들이기, 읽기 전의 저장 허용** — 다음 자동 저장이 그 위에 덮어써 내용이 영영 사라진다.
- **일괄 작업을 자산마다 저장하기** — 문서 전체를 자산 수만큼 쓴다.
- **최적화 파이프라인을 미들웨어에 다시 구현하기** — 순서(meshopt 가 마지막)와 정책이 두 곳에 있으면 `pnpm optimize:glb` 와 결과가 갈린다. 스크립트를 그대로 부른다.
- **조선소·분류를 태그와 따로 된 속성으로 두기** — 같은 구분을 두 군데에 적게 되고(분류 값은 전부 태그와 겹쳤다) 등록할 때마다 둘을 골라야 한다. 조선소는 `okpo`·`philly` 태그로 적는다.
- **태그로 동작을 가르기(런타임 자산 판정 등)** — 태그는 사용자가 고칠 수 있다. 팔레트 묶음(`indoor`·`outdoor`)만 예외이고, 그것은 사용자가 옮기라고 둔 것이다.
- **저장 버튼** — 자산 관리는 작업 하나가 곧 한 번의 기록이다. 미저장 상태가 없으니 이탈 경고도 없다.
- **목록에서 GLB 를 열어 통계·썸네일 만들기** — 수십 MB 지도가 목록을 여는 것만으로 내려온다. 통계는 표, 썸네일은 저장된 파일.
- **치수선에 브랜드 주황** — 주황 크레인과 섞여 읽히지 않는다.
- **지오메트리 AABB 를 월드 행렬로 옮겨 크기 재기** — 회전한 메쉬에서 상자가 부푼다. 정점 단위로 잰다.
- **썸네일 촬영 시점을 프레임 수로 짐작** — 캔버스 안은 별도 React 루트라 바깥 상태가 닿는 시점이 프레임과 맞물리지 않아 빈 그림이 찍혔다. 뷰어가 카메라를 맞춘 뒤 알린다.

- **뷰어의 접지 그림자(drei `ContactShadows`)** — 물체 발밑이 아니라 옆에 번진 얼룩으로 그려졌다. 크기가 수 cm 부터 수 km 까지인 자산에 한 설정으로 맞지 않는다.
- **썸네일 바탕의 모눈·카드마다 "씬에 n개" 표시** — 카드 수십 장에 반복되면 그림보다 무늬와 딱지가 먼저 보인다.
- **속성마다 테두리 있는 입력 상자** — 열 줄 넘게 늘어서면 값보다 상자가 먼저 보인다.
- **레일에 종류·상태·태그를 따로 줄 세우기** — 같은 자산을 여러 묶음으로 나눠 세면 "어디에 있는가" 가 보이지 않고 레일이 화면보다 길어진다. 위치는 계층 하나가 맡고, 태그는 그 계층의 펼친 종류 아래에만 놓는다.
- **태그 체크박스의 수를 고정값으로 두기, 체크한 태그를 위로 올리기** — 여러 개를 고르면 줄의 수와 누른 결과가 어긋나고, 체크할 때마다 줄이 뛰면 다음 것을 고르기 어렵다.
- **머리말의 화면 설명·종류별 큰 숫자, 카드 크기 조절** — 계층의 개수와 겹치고, 목록을 볼 자리를 줄인다.
- **자산이 없는 종류 마디 숨기기** — CAD 처럼 아직 비어 있는 자리가 어디인지 알 수 없게 된다.
- **게시된 자산마다 초록 점·네 단계 진행 표시** — 거의 모든 자산이 같은 표시를 달면 정작 진행 중인 것이 묻힌다.
- **카드의 그림·글 사이 가로줄, 카드에 수치 여러 줄** — 수십 장이 늘어서면 그림보다 줄과 숫자가 먼저 보인다. 카드는 이름과 상태까지만.
- **결과 수를 라이브러리 전체 대비로 적기** — 위치 안에서는 "57개 중 4개" 가 필터가 걸린 것처럼 읽힌다.
- **미리보기 열림 상태를 로컬 state 에 두기** — URL 과 두 벌이 되면 라우터 전환과 경쟁한다. `?preview=` 하나만 읽는다.
- **마우스 클릭으로 미리보기 접기** — 두 번 누름의 첫 클릭이 올리고 둘째 클릭이 내려 화면이 깜빡인다. 접기는 키보드(Space)와 닫기 버튼만.
- **비교 뷰어의 카메라 자세 그대로 복사** — 크기가 다른 두 버전에서 한쪽이 화면 밖으로 나간다.
- **높이 치수 꼬리표를 오른쪽 세로 모서리에 두기** — 납작하고 긴 물체에서 깊이 꼬리표와 겹친다.

## 미룬 것

- 현재 버전이 씬에 쓰이게 하기 — 씬이 파일 경로 대신 자산 id 로 참조해야 한다. 지금은 builtin 자산의 새 버전이 씬에 반영되지 않고(씬은 카탈로그 경로의 배포 파일을 쓴다), 등록한 자산도 이미 놓은 것은 옛 파일 그대로다.
- 등록한 지도를 편집 화면의 맵 탭에 내기, 팔레트에 지도·모델 외의 종류 내기.
- 등록한 배경을 편집 화면의 배경 선택에 내기, 배경의 사용처(씬의 `environmentId`) 보이기, 등록할 때 EXR 헤더 확인(해상도가 GPU 상한을 넘는 파일 — `scene-environment-catalog.ts` 의 주의).
- 자산 서버 — HTTP 저장소 구현, 권한(역할별 승인), 파일 잠금, 다단계 승인. 지금의 충돌 처리는 "쓰지 않고 다시 읽게 한다" 까지이고 변경을 합치지는 않는다.
- 목록 가상 스크롤(자산이 수천 개일 때), 여러 파일 한 번에 등록, 되돌리기(undo), 컬렉션 이름 바꾸기 화면.
- dev 저장 미들웨어의 접근 제한 — dev 서버가 사내망에 열려 있어(`host: true`) 같은 망에서 문서·파일을 쓸 수 있다. 인증·출처 확인·본문 크기 제한이 없다.
- CAD 원본(DWG·DXF·STEP·IGES) 미리보기와 GLB 변환, 도면 마크업.
- 태그 이름 일괄 바꾸기, 태그가 없는 자산만 골라 보기, 태그 가운데 "하나라도" 가진 자산 보기.
- 3D 위 주석(카메라 시점이 함께 저장되는 검토 코멘트), 반려 사유 입력, 저장된 사용자 정의 보기, 노드 트리·격리 보기.
